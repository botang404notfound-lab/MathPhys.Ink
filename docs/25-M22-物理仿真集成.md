# M22 物理仿真集成（CircuitJS / PhET + 原生运动学仿真）

> 目标：把"物理仿真"搬进白板。完整版走 **WebView2 加载离线仿真页**（CircuitJS、PhET），
> 轻量版走 **原生 WPF 运动学仿真**（单摆 / 弹簧 / 斜面）。两者共用 **1 颗工具栏瓦片**，
> 都能 **把画面落成卷面上可存档位图**。

## 2. 架构：三层 + 两条硬约束

```
插件（Plugin.WebSim / Plugin.NativeSim）
        │  只说"打开 / 关闭 / 发消息 / 抓帧"
        ▼
IWebPanelBridge（契约层，Plugin.Abstractions）
        ▲
WebPanelController（WebPanel/）  ← 全部逻辑：状态机 + 就绪闸门 + 互斥激活 + 消息编解码
        ▲
IWebPanelBackend（WebPanel/）  ← 替身可换，逻辑因此可 headless 断言
        ▲
WebView2PanelBackend（全工程唯一碰 WebView2 的文件）
```

### 硬约束一：空气空间（airspace）

WebView2 是 **HWND 子窗口**，Windows 的合成规则决定它**永远渲染在所有 WPF 视觉之上**，
且 WPF 渲染树里**没有**它的内容。两个直接后果：

1. 它**不能**叠在画布上 ⇒ 只有 **A3 全屏** 与 **A1 停靠**两种形态；
2. 想把它搬到卷面上，**只有**「浏览器侧抓帧 → 落成位图对象」一条路
   （用 `RenderTargetBitmap` 抓出来是空白 —— 别在这条路上浪费时间）。

原生 WPF 仿真没有这条约束（它就是 WPF 视觉），但它仍然做成**独立窗口**：
仿真要 60 Hz 重绘，而画布上的图形对象**没有**"每帧重绘"的推送通道，
硬塞进去会变成每帧一次 `UpdateNumbers`（昂贵，还会污染撤销栈）。

### 硬约束二：触控是"互斥激活"，不是"事件穿透"

进面板 = `EnterPanelMode()`（抑制画布输入、关视口手势）；退出 = `ExitPanelMode()`
（**把决定权还给当前工具**，而不是"设成能写字"）。
打开失败**必须回滚** —— 否则画布输入被永久抑制，白板再也写不出字，比"打不开面板"严重得多。

## 3. ★ 落地修正一：D5「1 颗瓦片」的正确做法

原设想是"工具族：代表 = Web 仿真、成员 = 原生仿真"。**读代码后否掉了** ——
`MainWindow.BuildToolButtons()` 里，族成员走 `VariantOf is not null ⇒ folded++ ; continue`，
**永不单独成瓦片**；而代表不在注册表时整条被 `continue` 跳过，二级菜单里也只筛
`byId.ContainsKey(m.Id)` 的成员。⇒ **轻量版裁掉 Web 插件后，族成员会连同瓦片一起彻底消失**，
正好砸中 D2（轻量版要留原生仿真）。

**改为「单工具 Id + 宿主侧可用性路由」**：

- 一个工具 Id：`phys-sim`「物理仿真」，由**两个变体都带的插件** `Plugin.NativeSim` 提供；
- 该工具打开的是**原生 WPF 仿真窗**（单摆 / 弹簧 / 斜面），**轻量版可用**；
- 窗口里再给「网页仿真：CircuitJS / PhET」入口，用
  `context.WebSim?.IsAvailable` **决定置灰 + 中文原因**（与 GeoGebra 工具完全同一套纪律）；
- 于是：完整版 1 颗瓦片、两个世界都能进；轻量版同一颗瓦片、只剩原生。

另：工具 Id 与分组/图标仍由宿主 `Tools/ToolCatalog.cs` 登记（`ITool` 成员零新增）。

## 4. ★ 落地修正二：S4 必须先于 S3 的"导出"按钮

原计划顺序 S3（原生仿真）→ S4（导出通道）。但 S3 的「导出到白板」**依赖 S4 建好的落画布通道**
（`Kind="webPanelImage"` + 渲染器 + `.twb` 图像段）。按原顺序写，S3 会带一个"接不上的按钮"。

**实际顺序：S1 → S2 → S4 → S3 → S5 → S6 → S7**，并把 S4 拆成两个可独立验证的半步：

| 半步 | 内容 | 验收 |
| --- | --- | --- |
| S4a | `IWebPanelBackend.CapturePngAsync` + WebView2 `CapturePreviewAsync` 实现 + 控制器转发 | 面板没开 → `null` 且不碰后端；开着 → 原样透传字节（**已落成 2 条断言**） |
| S4b | `Kind="webPanelImage"` 图形对象 + 渲染器 + `.twb` 图像段 + 面板「导出到白板」按钮接线 | 存档往返后图还在；导出 PDF 带上；撤销一步整体消失（**已落成 30 条断言，916/0**） |

### ★ 落地修正三（S4b 期间发现）：M12 题号牌的错题角标本来就画不出来

S4b 的像素探针（第 8.7 组）在演示「按 `ActualWidth` 画 = 一张空图」时，顺手量了既有的 M12 题号牌：
**未讲 103 个彩色像素 / 错题 0 个**。原因是 `QuestionMarkVisual.OnRender` 既读 `ActualWidth`
（图形层里恒为 0）又把矩形从 `(0,0)` 起画（应绕原点居中）。错题态是「红底白字」
⇒ 红底 0×0 等于不存在、白字压在白纸上 ⇒ **老师标了「错题」反而什么都看不见**。

已一并修掉（尺寸由 `Measure(obj)` 递进视觉 + 一切绕原点居中画），并落成第 8.8 组的三态像素回归。
详见 `docs/06` §31。

## 8. S3 落地记录（原生运动学仿真）

### 真机基线（`M10_UI_SHOT` 自出图，2026-09-26）

`toolbar = 500×649`（**没变**，与 M21 一致）、`tools = 23`、`tiles = 16`、`folded = 7`、
`other = 0`、`targets = 59`。账目自洽：`16 + 7 + 0 = 23`。
M21 基线是 22/15/7/58 ⇒ **正好 +1 颗瓦片、+1 个可点目标**，与「一颗 `phys-sim`」的设计一致。
`ui.chrome` 深/浅 = `#FF33332F` / `#FFE8E6E0`、`ink.红` 恒定、`ink.白` = `#FFF5F5F5` ——
换肤与墨色两条不变量都没被碰。

### 落地修正四（S3 期间发现）：**切模型必须重置模型**

三个模型的"当前位置"字段初值都是 0（摆角 0、位移 0），而"初始状态"是另一组值
（初始摆角 20°、初始振幅 0.25 m）。`SimWindow.SwitchKind` 原先只换 `_kind`，
于是**打开仿真窗时摆与弹簧一动不动地钉在最低点** —— 而右侧滑杆上的数字看着都对，
现场最容易被当成「坏了 / 点了没反应」。⇒ 抽 `ResetCurrent()`，切模型与「重置」按钮都走它。

★ 这是一类通用坑：**「参数」与「状态」是两套字段时，"切到某个模型"必须显式初始化状态**。
只搬参数不搬状态，界面会呈现一个「合法的静止」—— 那比报错难查得多。

### 落地修正五（S3 期间发现）：把"入口能不能用"抽成纯函数

「网页仿真入口该不该灰」的判定原先埋在 `SimWindow` 里，而它是 `internal` 的 WPF 窗口 ——
验收 harness 够不着，于是「轻量版那两颗按钮必须灰着并说清原因」只能靠真机肉眼确认。
⇒ 抽 `WebSimAvailability.IsUsable / Reason`（插件内 public 纯函数），
于是 harness 能用真 `WebPanelController` 把「有通道 / 通道自报不可用 / 通道没给原因 / 没有通道」
四种情况各断言一次。

★ 顺带定了一条界面纪律：**灰按钮必须说得出是哪一种不可用**。
不可用的来源至少三种（本版本没带 Web 模块、没装 WebView2 运行时、宿主较旧没给通道），
只说「不可用」等于没说 —— 现场无法区分"我该去装运行时"和"我手上这本就是轻量版"。

## 9. S5 落地记录（CircuitJS 接入）

### 设计要点：页 Id 是"货物"，profile 是"车厢"

`OpenAsync("circuitjs")` 里那个参数**不是** profile Id —— 它被控制器按 profile 的
`ArgsMessageType`（openArgs）与 `ArgsPayloadKey`（args）打包，经**就绪闸门**透传给
自建导航页，由导航页路由到 CircuitJS。于是 S6 接入 PhET 时：控制器零改动、profile 零改动，
只是导航页多一条路由 + 资源目录多一个子包。

### 「只做全屏」要三道闸，不是一道

物理仿真面板按 D3 只做全屏。但「没有停靠形态」不是一个开关能保证的：
① 窗内「停靠面板」按钮按 `AllowDockForm=false` **根本不摆**（摆出来再禁用，
老师还是会去点 —— 不如让那个动作不存在）；② 宿主 `Esc` 只接关闭、**不接 D 键**；
③ 后端构造仍需要一个停靠宿主，给一个**永远折叠、不在视觉树里的 Border 兜底**
—— 正常路径到不了它，真被误切进去也只是看不见，不会炸。

### 页面自检（selfTest）为 S7 包冒烟铺路

导航页带 `?selftest=1` 钩子：HEAD 探测 circuitjs 四件套（入口页 / nocache.js /
lz-string / fontello），结果回 `selfTest` 消息 —— 与 GeoGebra 页同一约定，
S7 的包本体冒烟照此断言「断网可用」，不靠人眼。

### S6 落地补充（PhET 钟摆实验）

选型：PhET 官方 **self-contained 单文件**（`sims/html/pendulum-lab/latest/pendulum-lab_zh_CN.html`，
3.6 MB，全部 JS/CSS 内嵌）—— 比拉整个 phet 资源库小两个数量级，且与
「官方文件一个字节不改」天然相容（iframe 直接指向它）。文件里的 9 处绝对外链
（遥测脚本、版权链接、一条官方构建里的 localhost 调试残留）离线时**静默失败**，
iframe 内的加载失败不冒泡到宿主 NavigationCompleted，不处理、记录备查。

取回脚本 `tools/fetch_phet.py`（与 fetch_circuitjs.py 同模式：唯一联网动作 + 自证 + 许可说明）。
导航页把 `showCircuit` 泛化成 `showSim(pageId, relPath)`、探测泛化成 `probe(rel)`（按路径缓存）——
**再接入第 N 个仿真 = 导航页一条路由 + 资源目录一个子包 + fetch 脚本一份**，
控制器 / profile / 契约层全都不用动。

### 踩坑：补丁脚本把行尾翻倍（`\r\r\n`）

harness 补丁脚本里，新文本先整体 `replace('\n', CRLF)` 预转了一遍，进 `sub()` 后又被
统一 `replace('\n', CRLF)` 一次 —— 已含 `\r\n` 的文本被翻成 `\r\r\n`，全文件 236 处行尾
变成"每行后面跟一个空行"。编译器不在乎（C# 把它当空行），但**源级断言在乎**：
任何按「单行」写的锚点都会因此失配。防法已固化：**行尾归一只在写盘前做一次**，
`sub()` 里只按已归一的风格匹配；补丁跑完必须回读 `\r\r\n` 计数（应为 0）。

### 断言口径上踩到的两条（都是**断言错**，不是产品错）

1. **门槛必须比被测物理量本身小**。单摆「Reset 之后真的动了」那条，我拿 `0.1 rad`（≈5.7°）
   当门槛，而 20° 起摆 0.5 s 后只回到 **0.4°** ⇒ 断言恒假。改成「确实离开了 0」。
2. **测试参数必须落在模型的量程内**。弹簧阻尼四态用 m=1/k=20 ⇒ `b_c = 8.94`，
   而阻尼量程上限是 3 ⇒ setter 把它夹到 3，于是「临界 / 过阻尼」两态**永远测不出来**，
   断言安静地报假失败。换成 m=0.2/k=1（`b_c = 0.89`）才测得到。

还有一条小口径：`Advance(0.5)` 内部拆成 500 步累加 ⇒ `Time` 是 `0.5000000000000003`，
**不能用 `== 0.5`**，要给容差。
