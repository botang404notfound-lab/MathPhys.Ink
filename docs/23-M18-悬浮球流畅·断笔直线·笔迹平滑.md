## 1. 日志分析结论

- 两台机器都是**红外触摸框 + 被动笔、笔报 Touch**（`stylus: type=Touch … ← 这台机器把笔也报成 Touch`）。
- 15班 M11 汇总：281 Hz、UI 收尾延迟 平均 5 ms / 最大 27 ms —— **书写性能本身健康**。
- **stylus up(1150) > down(1148)、touch up(1283) > down(1282)** ⇒ 丢的是 **Down** 而非 Up（红外框触点抖动/提升链丢 Down 的典型表现）。
- MaxSpeed 极值 250 world/ms —— 正常书写不可能，极可能就是"手掌并入点列的瞬移"被记进了统计（修复后应回落）。
- 退出时 8 条 ALC Unloading WARN 是 M15 热修的卸载绊线在进程退出时触发，**良性**。
- 悬浮球路径零埋点，卡顿靠代码证据定位。

## 2. P1 悬浮球 + 菜单拖动卡

### 根因
`FloatingBall.OnBallDrag` 每次 TouchMove 设 `XRatio/YRatio` → `ApplyPosition()` 改 `_ball.Margin`
→ 布局失效向上传播到 `CanvasOverlayGrid`，连带重测 TopChrome（40+ 按钮）与 ViewportHost。
菜单 Popup（`AllowsTransparency=true` 分层 HWND、`PlacementTarget=_ball`）跟着每帧 SetWindowPos 重合成。
与 M16 修工具栏前**完全同构**，悬浮球是 M16 改造的漏网之鱼。

### 修法（照 M16 FloatingDrag 先例，只动 FloatingBall.cs）
1. 拖动中**只改 `_ball.RenderTransform`（TranslateTransform）**，绝不碰 XRatio/YRatio/Margin；
2. 拖动开始即 `CloseMenu()` —— 分层窗口不再每帧重定位；
3. 松手才落 Margin（用拖动中的 `_current` 精确落，零跳变），再反推比例 → `PositionCommitted`
   （宿主接线与持久化协议不变，仍每次拖动只写一次盘）；
4. 点按分支（>6 DIP 判据 → BallClicked + ToggleMenu）原样保留；
5. `ApplyPosition` 拖动中短路；`LostMouseCapture` 清变换回退 Margin 位置。

## 3. P2 起笔直线（断点检测 + Reset 兜底）

### 根因（采样插件跨笔残留已被探查排除——字段全在 OnStylusDown 重置、只改压力不改几何）
1. **手掌并入同一点列**：红外框驱动把手掌触点与笔尖并入同一 StylusDevice 点列，点列从笔尖瞬移到手掌
   ⇒ DynamicRenderer 逐包增量连线（上包末点→新包点）把跳变画成横贯直线；软件层零手掌拒绝。
2. **Down 丢失后无 Down 续画**：UI 层没有 StylusDown，但笔线程 DynamicRenderer 收 Move 续画湿墨。
3. **打断无兜底**：工具/面板切换中途打断采集（IsHitTestVisible/EditingMode 翻转），湿墨残挂。

### 修法
- `Input/InkPointFilters.cs`（新增，纯函数层）：`JumpDetector.IsJump` **双条件**判定——
  速度 > 2.0 world/ms **且** 位移 > 80 world；长停顿(>120ms)+大位移也算；NaN 不判不抛。
  阈值推导：281Hz 相邻包 3.5ms、快笔每包仅 3.5~10 world；手掌到笔尖 >85 world。余量 8~20 倍。
- `InkSamplerPlugIn`：OnStylusMove/Up 采集**之前**用**原始点**检测（独立 `_rawLast*` 字段——
  平滑会把跳变抹开让检测失效）。命中 ⇒ `_jumpDetected` 置位 + **整包丢弃**（不采集不写回，保点数红线）
  + `TryResetRenderer()`。
- **清湿墨的线程论证**：`DynamicRenderer.Reset(StylusDevice, StylusPointCollection)` 官方签名，
  语义是"用给定点集**重画**当前湿墨"——传**空点集**即整截清掉，后续包从新位置继续画（不再与跳变前相连）。
  文档示例为 UI 线程调用、内部读笔/鼠标下落状态（线程亲和）⇒ 笔线程只置旗标，经
  `BeginInvoke(Send)` 投回 UI 线程执行（Invoke 会 RTI 死锁，铁律）。
- UI 侧兜底：`InkSurfaceCanvas.ResetActiveRenderer()`；`ApplyTool` 里调用一处覆盖三路
  （进出面板模式都走 ApplyTool）；`OnStrokeCollected` 里 `ConsumeJumpDetected()` 命中 ⇒
  `Strokes.Remove(e.Stroke)` 丢整笔——移除触发的新 StrokesChanged 落进**同一个撤销事务**，
  add+remove 净空，撤销栈不出现鬼影（已对照 InkHistory 事务机制确认）。

## 4. P3 笔迹温和平滑

### 关键事实
**手写 `FitToCurve` 出厂已是 true**（PenProfile.cs:36），提交后早就是 WPF 贝塞尔拟合。
观感差距来自：实时阶段是逐段折线（无拟合）+ 点抖动 + 起笔甩尾。

### 修法
- `PathSmoother`（纯函数）：**保点数指数低通** `s_i = s_{i-1} + α(p_i − s_{i-1})`，X/Y 独立、O(1)/点、
  **压力因子不动**（笔锋不磨平——docs/16 S5 红线：降采样/增删点都会破坏笔锋）。
  否决 Catmull-Rom/贝塞尔细分：会增点，改变 ISF 存档口径。
- 档位 `SmoothStrength Off/Light(α=0.6)/Medium(α=0.4)`，**独立于笔锋三档**；出厂 Light（延迟 ~2ms）。
- 首点锚定（首点不平滑）；起笔甩尾抑制：首 Move 包内与落笔点距离 <2 world 的点拉回重合（保点数）。
- 插件链序：**断点检测 → 平滑 → 采集 → 笔锋写回**。采集吃平滑后的点 ⇒ 统计口径=存档口径=实时口径；
  笔锋速度基于平滑点 ⇒ 宽度信号更稳。平滑开而笔锋关时由插件自己 `SetStylusPoints` 写回
  （否则平滑只活在 buffer 里）。
- UI：工具栏「平滑」复选框 + 两档（轻/中），与笔锋三件套同一套置灰逻辑。
- 不变量说明：平滑在**笔线程采集时一次成型**——提交几何=存档几何，之后永不重算；
  「笔迹几何永不重算」约束的是 UI 线程二次重算，未触碰。旧档点集不经过插件，原样渲染，零影响。

## 6. RunM18Checks（4 组）

1. **JumpDetector 行为**：快笔不误伤 / 瞬移必抓 / 停顿+大位移必抓 / 停顿小位移放过 / NaN 不抛。
2. **PathSmoother 行为**：点数不变 / 首点锚定 / 抖动能量（二阶差分和）砍半以上 / Off 恒等。
3. **悬浮球护栏**：OnBallDrag 切片**不含 Margin/XRatio**（拖动零布局属性）+ 含变换/收菜单；
   松手切片含落 Margin/清变换/持久化；ApplyPosition 含拖动短路。
4. **接线护栏**：插件断点+平滑锚点；墨迹层 Reset 空点集；宿主兜底+丢笔；窗口平滑档位。

## 8. 已知边界

- 断点检测双条件是防误伤与防直线的折中：极快的整臂横扫（>2 world/ms 且单包 80 world）理论上会被截断——
  正常教学书写到不了这个量级；真机若出现误截，调小 `JumpMinDistance`/`JumpSpeedThreshold` 即可。
- 平滑 Light 档相位延迟 ~2ms，真机若仍觉迟滞：勾掉「平滑」即回 M17 手感，零代码改动。
- 平滑后的点集即存档点集（不可逆、有意为之）；M17 之前的旧档不受影响。
