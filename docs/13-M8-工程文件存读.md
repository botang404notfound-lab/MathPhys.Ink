# M8 工程文件存读 —— 设计与实施方案

> 目标：把「批注」从 PDF 同目录的 `.tbink` 侧车，提升为**带路径的工程文件 `.twb`**，
> 让老师可以「打开工程」一键恢复（PDF + 笔迹 + 图形 + 视图状态），并由关闭提示挡住
> 未保存的改动。
>
> 插件完全冻结（M8 期间不动 7 个插件、不新建、不删除）。

## 0. 范围与边界

### 0.1 做什么

- 新建 / 打开 / 保存 / 另存 / 关闭 `.twb` 工程文件
- `.twb` 内嵌 PDF（embedded）或引用 PDF（referenced），由 manifest 写明
- 视图状态（当前页 + 缩放 + 平移 + 是否全屏）进 manifest
- 关闭工程 / 关闭窗口前：未保存 ⇒ `保存 / 丢弃 / 取消` 三选
- 写 `.twb` 后删除同目录 `.tbink`（迁移完整，不留"两边挑一个"的歧义）

### 0.2 不做什么

- 多 PDF 同一工程
- 工程文件的云端/多人协作
- 板书回放 / 演示模式 / 导出 PNG/PDF（留给后续 M9~M11）
- 外挂 PDF 的"按文件指纹找"逻辑（M8 外挂仅按**路径**找；找不到弹定位对话框）
- 菜单（M8 仍走工具栏）

### 0.3 与 M7.x 的兼容契约

- **读**：打开 PDF 仍检查同目录 `.tbink`；M7.x 老师无感
- **写**：进入工程模式后不再写 `.tbink`，改写 `.twb`；首次保存 `.twb` 时**删除** `.tbink`
- **契约零新增**：不动 `ITool`、不动 `IGfxTool`、不动插件加载机制（M8 不依赖任何插件变更）

## 1. 关键设计抉择（用户已确认）

| 决策 | 选项 | 结果 |
|---|---|---|
| PDF 与工程的关系 | 嵌入 + 外挂都做 | manifest 里 `pdfEmbedding: "embedded" \| "referenced"` |
| 与 .tbink 兼容 | 写 .twb 后删 .tbink | 工程模式下 `.tbink` 不再被写也不留存 |
| 视图状态 | 进 manifest | 复原"上次停在哪页就停在哪页" |
| 插件 | 完全冻结 | 7 插件零改动 |

## 2. .twb 容器格式

标准 ZIP 容器（`System.IO.Compression.ZipArchive`，**不引入新依赖**）：

```
manifest.json        # 工程元信息
document.pdf         # embedded 模式时存在
annotation.tbink     # 复用现有 v2 协议（InkHistory + GfxObject JSON）
```

### 2.1 manifest.json

```json
{
  "schemaVersion": 1,
  "title": "26西附全真模拟1物理试卷",
  "createdUtc": "2026-09-22T13:08:42Z",
  "updatedUtc": "2026-09-22T13:30:11Z",
  "pdf": {
    "embedding": "embedded",         // or "referenced"
    "relativePath": null,            // embedded 时为 null
    "absolutePath": null,            // embedded 时为 null
    "fingerprint": "sha256:..."      // 16 位短指纹（与 .tbink 同一函数）
  },
  "view": {
    "pageIndex": 0,                  // 0-based
    "scale": 1.0,
    "offsetX": 0.0,                  // 视口左上角在世界坐标中
    "offsetY": 0.0,
    "isFullScreen": true
  },
  "stats": {
    "strokeCount": 142,
    "objectCount": 5
  }
}
```

**复用原则**：
- `pdf.fingerprint` 用现有 `DocumentFingerprint.Compute(path)`，**不发明新算法**
- `view` 字段全部 world 单位（与 M2 起的世界坐标铁律一致）
- `stats` 仅诊断用，加载侧**不**据此判定内容

### 2.2 文件层错误码（写入策略与 .tbink 一致）

- ZIP 写入走 `using var fs = FileStream(path, FileMode.Create, ...)`；不引入临时文件 + 替换（ZIP 库自带事务语义失败 ⇒ 直接删坏文件）
- 异常一律 `AppLog.Warn` + 状态栏中文；不弹 `MessageBox`（自动保存触发时弹窗会变成打地鼠）

## 3. 模块设计

### 3.1 新增 `Ink/TwbManifest.cs`

POCO：上面 JSON 的形状。`System.Text.Json` 默认策略（同 `TbinkFile`），
`JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，让 manifest 用记事本打开也能读懂。

### 3.2 新增 `Ink/TwbFile.cs`

静态类，三个方法：
- `Write(string twbPath, TwbManifest manifest, byte[] pdfBytes, byte[] tbinkBytes)`：把 PDF 与 .tbink 嵌入 ZIP
- `TryRead(string twbPath, out TwbManifest manifest, out byte[]? embeddedPdf, out byte[] tbinkBytes, out string error)`
- `ReadAnnotationBytes(byte[] tbinkBytes)`：转手给 `TbinkFile.TryRead`（**不动 .tbink 协议**）

**契约**：所有方法均返回可读错误，不抛异常（与 `TbinkFile` 一致）。

### 3.3 新增 `Ink/ProjectStore.cs`

工程装载/保存的**唯一入口**，把 `.twb` 协议变成宿主看得懂的结果。

```csharp
public sealed class ProjectStore
{
    /// <summary>把当前 PDF + .tbink 字节 装成 .twb（嵌入/外挂由调用方决定）。</summary>
    public ProjectSaveResult Save(string twbPath, TwbManifest manifest, byte[] pdfBytes, byte[] tbinkBytes, bool deleteSidecarTbink);

    /// <summary>读一个 .twb，返回 manifest + 嵌入 PDF 字节（referenced 时为 null）+ .tbink 字节。</summary>
    public ProjectLoadResult Load(string twbPath);

    /// <summary>外挂模式：按 manifest 路径找 PDF；找不到返回 FileNotFound 错误。</summary>
    public PdfResolutionResult ResolveReferencedPdf(TwbManifest manifest, string? userPickedPath = null);

    /// <summary>写完 .twb 后删同目录 .tbink（仅当 .tbink 存在且不是只读时）。</summary>
    public static bool DeleteSidecarTbink(string pdfPath);
}

public sealed record ProjectLoadResult(
    bool Ok,
    TwbManifest? Manifest,
    byte[]? EmbeddedPdf,           // 仅 embedded 时非 null
    byte[] TbinkBytes,             // 永远非 null（空工程时为 length=0）
    string Error,
    ProjectLoadStatus Status);     // Loaded / LoadedWithMismatch / MissingPdf / Rejected

public sealed record ProjectSaveResult(
    bool Ok,
    bool Written,
    string Message,
    bool SidecarTbinkDeleted);
```

**判定规则**（参照 `AnnotationStore.Load` 的四重判定）：
- ZIP 损坏 / 缺 manifest → `Rejected`，附原因
- `pdf.embedding == "embedded"` ⇒ 用包内 PDF
- `pdf.embedding == "referenced"` ⇒ `ResolveReferencedPdf` 按路径找；找不到 ⇒ `MissingPdf`，UI 弹"定位 PDF"对话框
- 找到 PDF 后与 manifest 的 fingerprint 比对：一致 `Loaded`；不一致 `LoadedWithMismatch`（黄字提醒）

### 3.4 新增 `ViewModels/ProjectViewModel.cs`

宿主侧的工程视图模型（只新增，不动 `DocumentViewModel`）：

```csharp
public sealed class ProjectViewModel : ObservableObject

```

  ```csharp
  private byte[]? ComposeTbinkBytes()
  {
      // 把当前笔迹与图形 → .tbink 协议字节（共用 TbinkFile.Write 到 MemoryStream）
  }

  private bool SaveAnnotationsNow()
  {
      if (_project.HasProject)
  ```

### 3.8 `OnDocumentChanged` 的扩展

当「关闭工程 / 切到无工程」时，`Document.Clear()` 已存在；新增"工程下打开新 PDF"的处理：
- `NewProject`：先 OnClosing 提示 → 写空 .twb → 宿主不开 PDF（老师想从空白开始）
- `OpenProject`：先 OnClosing 提示 → ProjectStore.Load → 拿嵌入/外挂 PDF 字节写到临时文件
  → `PdfService.Open(tempPath)`
  - **临时文件**：`Path.GetTempFileName()` + `.pdf`，`ProjectStore.Load` 后由 MainWindow
    负责清理（`OnClosed` 里删）
- `OpenPdf`：老行为；不动

## 4. 错误处理矩阵

| 场景 | 行为 |
|---|---|
| 打开 .twb 时 ZIP 损坏 | 弹 MessageBox「工程文件已损坏」，不让开；不丢当前内容 |
| 外挂 PDF 找不到 | 弹 OpenFileDialog（标题：「找不到引用的 PDF，请定位」），可取消；取消则工程也不开 |
| 外挂 PDF 指纹不符 | 黄字提醒，照常装载（参照 .tbink 的 LoadedWithMismatch） |
| 保存 .twb 时磁盘满 / 只读 | 日志 + 状态栏黄字；`IsDirty` 保留；不弹窗（自动保存触发场景） |
| 手动保存失败 | 弹 MessageBox 一次（手动操作可接受弹窗） |
| 删除 .tbink 失败（只读 U 盘） | 状态栏提一句；不阻断（工程已经落盘） |

## 8. 风险与备选

| 风险 | 应对 |
|---|---|
| ZIP 写入半路断电 → 工程文件坏 | 与 .tbink 一致靠底层 ZIP 库的临时文件语义；M8 范围内不引入"双副本 + 校验" |

| 多工程并发（M8 不做） | UI 层只允许单工程；不做锁 |

**结果**：主工程与 harness 均 **0 警告 0 错误**；全量回归 **483 → 525 PASS / 0 FAIL**。

**包内结构（与 §2 一致）**：`manifest.json`（deflate） + `document.pdf`（**stored**，仅 embedded）
+ `annotation.tbink`（deflate，空工程不写该条目）。产出的 `.twb` 实测：内嵌 513 KB / 外挂 1.0 KB / 空白 0.95 KB。

**★ 实施中对设计稿的 4 处调整**（均为 S0 阶段暴露的必需项，已在 docs/06 §9 记录成因）

| # | 调整 | 原因 |
|---|---|---|
| 1 | **新增第三种绑定方式 `embedding = "none"`** | 设计稿只有 embedded / referenced。但「新建空白工程（还没插试卷）」两种都表达不了：referenced 无路径会被读侧判成损坏，embedded 无内容自相矛盾。而 §7 验收标准里明确有「新建工程（空）→ 写几笔 → 重开恢复」 |
| 2 | **manifest 新增 `integrity` 段（各载荷 SHA-256）** | 实测 `.NET ZipArchive` 读 **stored 条目不校验 CRC**：改坏 `document.pdf` 1 个字节仍静默放行。这与"绝不静默损坏"的项目铁律冲突，必须自存校验值 |
| 3 | **`Write` 采用「临时文件 + 原子替换」**（设计稿 §2.2 原写"不做"） | 原稿理由是"ZIP 库自带事务语义"——实测不成立：`FileMode.Create` 会**先截断原文件**，写到一半失败即同时毁掉新旧两版。改为与 `AnnotationStore.Save` 同一套成熟套路 |
| 4 | **比设计稿多 3 个方法**：`Write(Stream)` / `TryReadManifest` / `ExtractEntry` | 分别是：harness 造坏文件、外挂模式打开前的轻量预检、内嵌 PDF 落临时文件（走流避免 30 MB 在托管堆上多留一份副本） |

**未实现的一项**：设计稿的 `ReadAnnotationBytes(byte[])` —— 只是个转发壳，
直接调 `TbinkFile.TryRead` 即可，不加无价值的中转层。

**S0 断言覆盖面**（41 条）：内嵌全字段往返 / 字节原样穿过 ZIP / ZIP 魔数 / 条目命名 / stored 存放 /
明文可读（中文不转义）/ camelCase；外挂模式（路径保留、无 PDF 条目、包体更小）；
空白工程；空批注不写条目；覆盖写原子性；**10 条错误路径**（不存在 / 非 ZIP / 截断 / 缺 manifest /
版本过高 / 版本 0 / 坏 JSON / 内嵌却缺 PDF / 未知绑定方式 / 外挂无路径）；
前向兼容（未知字段不拦读）；**内容被改坏必被拒绝**（PDF 段、批注段各一）；
写入侧拦截（非法路径、声明内嵌却没给内容）；保存失败不留 `.tmp` 残骸；抽条目；只读元信息。

**非空验证（防假绿）**：断言确实是"抓得住"的 —— 首轮 41 条里 2 条 FAIL（外挂无路径用例的
前提被自己的助手写歪 + stored 条目改坏后静默放行），修完才转绿；修 `.tmp` 残留时又有 17 条 FAIL
（在 `using` 内做替换导致文件占用），说明断言网跟着真实调用链在动，不是空转。

### S1：ProjectStore 服务层（2026-09-23）

**分工**：`TwbFile` 管"字节怎么摆"，`ProjectStore` 管"这份工程能不能用"。判定顺序刻意是

**对设计稿的调整**

**★ 真 bug 1：启动时装工程 ⇒ 主窗口"不可见"**

`ApplyStartupArgument()` 原本在构造函数里同步执行。命令行带 `.twb` 启动、工程是 `referenced` 且试卷不在原位时，

真机冒烟的「主窗口起来」那条因此 FAIL（脚本在对话框弹着的时候找不到主窗口）。
修法：把入口挪到 `Loaded` 事件后（一次性退订）。**"构造里绝不弹模态框"应当作为一条通用纪律记下来** ——
它不会崩、只会让用户看到半截界面。

**★ 真 bug 2：打开工程后首屏一片白（存档位置白存）**

两个问题叠在一起，探针（`TB_RENDER_TRACE=1` 渲染追踪日志）分开它们：

1. **存档视口可能落在页面之外。** 排版把页面放在 `(960,960)` 起排、四周留 960pt 可写留白
   （`WorldLayout.DefaultPageMargin`），所以 `100%@(0,0)` 看到的是**一片纯白留白区**。
   实测该状态截图 `std=0.00 / mean=255`（整屏纯白）—— 在老师眼里和"文件根本没打开"**完全无法分辨**。
2. **更要紧的：原来那份正确视口会被随后的自动适应覆盖。** `CanvasViewport.SetView` **不触发**
   `ViewportMutated` ⇒ `_autoFitWidth` 仍为 `true` ⇒ 窗口下一次改尺寸就把存档位置整个算掉。
   也就是说"我停在第五题那个缩放"从来就存不住，只是平时不容易察觉。

修法两件事一次做掉（都在宿主里，窗口侧只调一个入口）：

- `CanvasViewportHost.RestoreView(scale, x, y)` —— **复原 = 用户意图 ⇒ 显式 `_autoFitWidth = false`**；
- 纯函数 `ProjectComposer.IsViewUsable(scale, x, y, 视口尺寸, 世界范围)` 判"按存档摆好后可见范围是否与页面相交"，
  坏档兜底回适应宽度并留痕（`[视图] 存档视口 … 看不到任何页面，已退回「适应宽度」`）。

做成纯函数是因为这段判定在界面上的唯一表现就是"白屏和白纸长得一样"，靠肉眼验收碰不出来。

**S2 断言覆盖面**（32 条）：`ProjectComposer`（默认标题空/有 PDF、页码反推含页间空隙取最近、

**★★ 真 bug：图形对象的改动不算"改动"**

`InkChanged` 原来**只从 `OnStrokesChanged` 触发**。图形对象（坐标系 / 函数图像 / 三角板 / 矢量箭头）

**安全性核对**：`GfxObjectStore.Restore` 也会触发 `Changed`（装载期），
