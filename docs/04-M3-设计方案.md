# M3 设计方案 —— 笔迹层接入（成败验证点）

> 前置：`docs/01-设计方案-PDF导入与无限画布.md`（图层栈与坐标变换）、`docs/03-M2-设计方案.md`
> 本文只覆盖 M3 范围。

---

## 1. 目标

一句话：**让笔迹落在世界坐标里，跟随画布缩放平移，永不漂移。**

| 做 | 不做 |
|---|---|
| `InkCanvas` 挂进世界层，笔迹存世界坐标 | 压感（M4） |
| 笔/指分工：**触摸与手掌不落墨** | 笔尾擦除实现（M4，只先抑制） |
| 笔宽按**世界单位**（纸面恒定） | 撤销重做（M5） |
| 笔/手两态临时开关、清空笔迹 | 笔迹持久化（M6） |
| 端到端光栅断言（笔迹与 PDF 同变换） | 工具框架 / 插件（M7） |

---

## 2. 先诊断：M2 留下的三个问题

这三个不解决，M3 一接进来就会坏：

| # | 现状（`CanvasViewportHost.xaml.cs`） | 后果 |
|---|---|---|
| 1 | 左键拖动 = 平移（`OnMouseDown` 的 `panButton` 含 `MouseButton.Left`） | 笔要用左键写字 ⇒ **输入分工必须重排**，否则"边写边平移" |
| 2 | 只有一道"触摸被提升成鼠标"的闸门（`_activeTouches`） | `InkCanvas` 引入后触摸还会被提升成**笔**事件 ⇒ **手指会在试卷上画出墨**，一体机上立刻可见 |
| 3 | 世界原点 = 首页左上角，包围盒 = 页并集 | 墨迹要写在页外（页边批注、页间空隙）就必须覆盖比并集更大的范围；若把 `InkCanvas` 放到负坐标，它的**本地原点就与世界原点错开一个常量**，之后保存、擦除命中、导出 PDF 每一处都得记得补偿 —— bug 温床 |

## 3. 设计

### 3.1 落位：为什么"零坐标补偿"是成立的

```
Grid RootGrid            ClipToBounds=True，尺寸 = 视口
└ Canvas WorldHost        RenderTransform = MatrixTransform(WorldToViewport)   ← 全局唯一的矩阵
  ├ Canvas  PdfPageLayer  页矩形 + Image，Canvas.Left/Top = 世界坐标
  └ InkCanvas InkLayer    Canvas.Left/Top = (0,0)，尺寸 = InkExtent，Background = Transparent
```

成立条件只有两条：**它是 `WorldHost` 的直接子元素**、**它的本地原点落在世界原点上**。于是：

- **输入侧**：WPF 把笔尖的视口坐标过一遍 `WorldToViewport` 的逆矩阵，再交给 `InkCanvas` 存成 `StylusPoint` ⇒ **`Stroke` 里存的就是世界坐标**，没有任何手工换算。
- **渲染侧**：`InkCanvas` 的可视化被祖先的 `RenderTransform` 变换 ⇒ 和 PDF 用**同一个矩阵**。
- 缩放平移改变时**只有矩阵变，笔迹几何一个字都不改** ⇒ 不重算、不漂移、不卡。

> 有意为之：矩阵放在**祖先**上，不放在 `InkCanvas` 自己身上。
> 祖先变换对输入与渲染两侧由 WPF 统一处理；而给 `InkCanvas` 直接加 `RenderTransform` 会同时牵扯它自己的命中测试与湿墨渲染路径 —— 那是本机无法验证的区域，不碰。

两个必须写对的细节：

- **`Background = Brushes.Transparent` 是必需的。** 透明 ≠ 不可命中：`Background=null` 的元素只在**画了内容的像素**上响应命中，于是整片空白区收不到笔输入。必须给一个透明画刷。
- **`InkCanvas` 必须挂在 `PdfPageLayer` 之后**（z 序在 PDF 之上）。

### 3.2 世界原点与可写范围：让 `InkExtent` 的原点恰好是世界原点

给 `WorldLayout` 加一个 `PageMargin`（默认 **960** world 单位 ≈ 339 mm，初版曾取 96 —— 见 §10.3），**页面从 `(M, M)` 开始排版**：

| 量 | 值 | 说明 |
|---|---|---|
| `WorldBounds` | `(M, M, W, H)` | 页并集（FitWidth 用它） |
| `InkExtent` | **`(0, 0, W+2M, H+2M)`** | 页并集外扩 M ⇒ **原点 = 世界原点** |

`InkCanvas` 放在 `(0,0)`、尺寸 = `InkExtent` ⇒ **本地坐标 ≡ 世界坐标**，偏移恒为 0。

**对既有行为零影响**：`FitToWidth` 本来就是"按包围盒宽度适配再减去包围盒原点"，页面的最终像素位置完全不变 ——
fit-width 观感一模一样。harness 里"首页 Y 应为 0"这一条改成"应为 `PageMargin`"，其余断言不变。

### 3.3 笔宽语义：世界单位（纸面恒定）

`DrawingAttributes.Width/Height` 的单位就是墨迹坐标系单位 = **世界单位 = PDF point**。

> ⇒ 笔画粗细跟着缩放走。**"墨是落在纸上的墨"**，这是正确语义（OneNote / Word 的手写同理）。

默认 `PenProfile.WorldWidth = 1.5`（≈0.53 mm），`IgnorePressure = true`（M3 不要压感），`FitToCurve = true`（平滑）。

| 场景 | 屏幕上看到的笔宽 |
|---|---|
| 4K 一体机 fit-width（scale ≈ 6.37） | ≈ 9.6 DIP ≈ 2.5 mm，写字很清楚 |
| 100% | 1.5 DIP，像细钢笔 |

**伴随效果（不是 bug）**：同一笔画放大看会变粗。这是"笔宽属于纸张"的必然结果。

### 3.4 笔/指分工（`Input/InkInputPolicy.cs`）

一体机上手指、手掌、笔尖同时存在，规则必须是**显式的纯逻辑**，才能被 harness 断言、也才能在设备上对账：

| 输入 | 判定依据 | 动作 |
|---|---|---|
| 真实笔 | `TabletDeviceType.Stylus` | **落墨** |
| 笔尾反转（橡皮） | `StylusDevice.Inverted` | **抑制**（M4 换成擦除）—— 不抑制的话反转笔会在试卷上画出墨，是设备上立刻可见的缺陷 |
| 触摸 / 手掌 | `TabletDeviceType.Touch` | **抑制**（交给 Manipulation 去平移缩放）—— 顺带天然实现**手掌拒绝** |
| 鼠标 | 也报成 `TabletDeviceType.Stylus` | **落墨**（与笔同支） |

> **实施时修正**：`TabletDeviceType` 枚举**只有 `Stylus` 和 `Touch` 两个值**，没有 `Mouse` ——
> WPF 把鼠标的平板设备也报成 `Stylus`。所以"鼠标单独一支"这个设计是错的，
> 鼠标天然与真实笔同支、在笔模式下落墨（这正合我意：本机只有鼠标，不放行就没法验证墨迹层）。
> 判定的完整输入空间只有 `2 工具 × 2 设备类型 × 2 反转 = 8` 种组合，harness 已**穷举**这 8 种。

实现：在 `InkCanvas` 上挂 `PreviewStylusDown/Move/Up`，命中"抑制"就 `e.Handled = true`。
用**预览**阶段拦截，`InkCanvas` 的内部采集器就根本收不到事件。

**诊断日志**：前若干个 stylus-down 事件把 `TabletDeviceType / TabletDevice.Name / Inverted` 记进 `AppLog`（有上限，不会刷爆日志）。
理由：§3.4 的抑制依赖"WPF 把触摸提升为 `TabletDeviceType.Touch` 的笔事件"这一行为，**本机没有触摸屏无法触发**。到一体机上实测时，读这一行日志就能直接判定它对不对。

### 3.5 工具占位：笔 / 手（临时）

M2 左键 = 平移；M3 起左键要用来写字。

| 工具 | 左键拖动 | 中键拖动 | 单指拖动 | 双指 |
|---|---|---|---|---|
| **笔**（默认） | 写字 | 平移 | 平移 | 缩放 |
| 手 | 平移 | 平移 | 平移 | 缩放 |

`InkLayer.EditingMode = Ink / None` 直接切换。

**为什么现在就加**：不加的话，只有触控板的笔记本上要么不能平移、要么不能写字。它约 20 行、不进 ViewModel、不建立任何工具框架。
**明确标为临时占位**：M4/M7 会用正式工具系统（`ITool`）替换它，届时这个东西会被删掉。代码注释里会写死这一点。

### 3.6 事件归属（防双重响应）

`InkCanvas` 铺满可写范围且可命中，它就是画布最上层的命中目标。于是：

- **鼠标**：host 的 `OnMouseDown` 只在**中键**、或**手工具**时才进平移分支。
  这里刻意**不去依赖"InkCanvas 有没有把事件标记为已处理"** —— 那属于别人的实现细节，靠它迟早踩空。
- **滚轮**：`InkCanvas` 不消费，冒泡到 host ⇒ 缩放行为不变。
- **触摸**：§3.4 已抑制，不被 `InkCanvas` 消费 ⇒ host 上的 Manipulation 照旧。

### 3.7 清空笔迹

`InkLayer.Strokes.Clear()`。换文档 / 关闭文档时也清空（防止旧笔迹残留到新试卷）。
M3 没有撤销（M5），所以工具栏按钮加一次确认。

## 5. 验证标准（harness 断言）

M1 / M2 全部断言保留作回归。M3 追加：

| # | 断言 | 为什么这条必须有 |
|---|---|---|
| 1 | `WorldLayout` 加 `PageMargin` 后：页矩形起点 = `(M,M)`；**`InkExtent.X == 0 && InkExtent.Y == 0`**；`InkExtent` = 页并集外扩 M | 这是"本地坐标 ≡ 世界坐标"的前提条件 |
| 2 | 实例化**真实控件树** `CanvasViewportHost`，`Measure/Arrange` 后取 `InkLayer.TransformToAncestor(host)`：世界点 `w` 经它映射到的视口点 == `viewport.ToViewport(w)`（多组视口状态） | 钉死"InkCanvas 本地坐标就是世界坐标"，即**没有任何意外的偏移或缩放** |
| 3 | 同一张图上，**页 `Image`** 与 **`InkCanvas`** 两条变换链映射同一个世界点 → 得到同一个视口点 | 两层同变换 ⇒ **相对漂移在数学上不可能**（这是 M3 的核心命题） |
| 4 | **端到端光栅**：`RenderTargetBitmap` 渲染整个宿主；在已知世界点放一条**红**笔画；断言光栅里红像素质量中心 == `ToViewport(w)`（fit-width / 100% / 放大 3× 带平移，≥3 组状态）；同时断言白纸区外接框 == `ToViewport(pageRect)` | 唯一能**端到端证明"笔迹随画布变换不漂移"**的证据，且不需要窗口、不需要触摸屏 |
| 5 | `InkInputPolicy`：笔→落墨；笔尾反转→抑制；触摸/手掌→抑制；手工具→全抑制 | 纯逻辑；一体机上没机会逐个试 |
| 6 | `PenProfile`：`DrawingAttributes.Width == WorldWidth`、`IgnorePressure == true` | 若这里被写成屏幕像素，笔宽会随缩放乱变 |
| 7 | 换文档后 `InkLayer.Strokes.Count == 0`，且 `InkExtent` 按新文档重算 | 防旧笔迹残留到新试卷 |

第 4 条是最有价值的：它把"渲染、布局、变换、笔迹"四层**一次比对完** —— 红像素质心对不上，就说明某一层错了；对得上，就说明它们全部同变换。

**两条已知的工程细节（可预见，非未知风险）**：
- `RenderTargetBitmap` 要求布局已完成 ⇒ harness 手动 `Measure/Arrange`，不开窗口。
- 参与光栅的内容是"位图 + 笔迹几何"，**没有 ClearType 文本**，避开 `RenderTargetBitmap` 的经典雷区。
- 在控制台里 new 一个 `UserControl` 需要从被引用程序集加载 BAML。若加载失败，退路是 `Application.ResourceAssembly` 指定程序集或 `new Application()`；再不行就退化成"按同样的放置规则手工搭一棵镜像树"。**这条会在实施时第一时间验证**，不会拖到最后。

## 6. 已知限制（明确接受，免得以后被当 bug 修）

1. **`scale > 6` 是位图拉伸**（继承 M2，瓦片渲染列 M9）。
2. **没有撤销**：写错了只能"清除笔迹"整片清空（M5）。
3. **笔迹不持久化**：换文档 / 关程序即丢（M6）。
4. **没有压感、笔尾不能擦**（M4）。
5. **可写范围有界**（= `InkExtent`）：页外 339 mm 之内能写，再远写不了。那需要一张近乎无限尺寸的 `InkCanvas`，会同时拖累命中测试与内存，不做。注意**页宽适配时左右留白在屏幕外**（页宽 + 2×留白 ≫ 视口宽），要写页外批注得先缩小或平移 —— 若实际用起来别扭，`DefaultPageMargin` 是一行参数。
6. **笔迹不参与页归属**：所以暂时做不到"只擦本页"。M4/M5 再引入页归属。

## 7. 本机无法验证的三件事（都要到一体机上验，我会给一份清单）

1. **湿墨（`DynamicRenderer`）的落位。**
   笔尖落下到抬起的实时墨迹由 `InkPresenter` 的 `DynamicRenderer` 绘制，它和最终笔迹走同一棵可视化树，理论上同变换 ——
   但**这条路径在 harness 里伪造不了笔输入，断言不了**。
   若实测表现为"写字时墨在正确位置，抬笔后一跳"，说明湿墨没吃到祖先矩阵；备选方案是关掉 `DynamicRenderer`、只保留抬笔后显示（牺牲实时感，但不会错位）。
2. **触摸是否真的不会落墨。** §3.4 的抑制依赖 WPF 的触摸→笔事件提升行为，本机没有触摸屏触发不到。实测时看 `AppLog` 里那行 `stylus down: type=...`。
3. **笔尾反转是否被识别为 `Inverted`。** 本机没有笔。这条本是 M4 的正题，M3 只做"抑制"。

### 实施中发现并修正的三处

1. **`TabletDeviceType` 没有 `Mouse` 成员**（该枚举只有 `Stylus` / `Touch`）。
   原方案 §3.4 把"鼠标"单列一行是错的 —— WPF 把鼠标的平板设备也报成 `Stylus`，
   于是鼠标与真实笔落在同一分支（在笔模式下落墨，正合需要：本机只有鼠标，不放行就没法验证墨迹层）。
   已把判定空间收敛为 `2 工具 × 2 设备 × 2 反转` 的 **8 种组合并穷举断言**。
2. **harness 的 M1 断言"首页 Y 应为 0"改为"应为 PageMargin"** —— 这是 §3.2 预告过的预期变更，不是回归。
3. **`IsHitTestVisible` 是必要的**：`EditingMode=None` 只表示"不采集墨迹"，
   它是否仍吞掉鼠标事件属 `InkCanvas` 内部实现细节。手工具下直接把命中测试关掉，
   平移手感才是确定的。

## 10. M3 后补丁（2026-09-20 用户拍板后实施）

### 10.1 `FitWidth` 落点：采用方案 B（只改宽度）

`CanvasViewport.FitToWidth` 原本是"整份文档竖直居中"：7 页试卷按 1000 px 视口适配后
世界高≈9660 DIP，居中会把视口送到第 4 页 —— 而"打开试卷"期望看到**第一页顶部**。

**已改为方案 B**：宽度照旧按页并集铺满，竖直方向"保持当前视口中心的世界 Y"，再夹紧到内容范围内。
新增私有函数 `FitVerticalOffset(worldBounds, viewportHeight, scale, oldScale, oldOffsetY)`：

| 情形 | 行为 |
|---|---|
| 内容比视口高（长文档） | 保持视口中心的世界 Y；夹紧到 `[视口高 − 内容底×scale, −内容顶×scale]` |
| 内容比视口矮（单页文档） | 竖直居中（与旧行为一致，小文档没有落点问题） |

由此得到三个确定行为：**打开文件→首页顶部**；**看到第 5 页按 Ctrl+0→停在第 5 页**；**越界时夹紧，不会停在空白处**。

### 10.2 补做：换文档必须重置视口（`CanvasViewport.Reset()`）

10.1 的"保持视口中心"带来一个副作用：**换文档时若沿用上一份文档的视口位置，新试卷也会落在中部**。
这与"打开试卷看第一页"直接冲突，所以 `CanvasViewportHost.SetDocument` 里在 `FitWidth` 之前加了
`_viewport.Reset()`（回到 100% + 世界原点）。于是 `SetDocument → Reset → FitWidth 夹紧` 三步下来，
**任何前置状态下打开/换文档都从第一页顶部开始**；而 Ctrl+0（适配宽度）仍然保留当前位置。

### 10.3 页外可写留白 96 → 960 world 单位

96 pt（≈34 mm）实测太窄，连一道旁批都写不下。`WorldLayout.DefaultPageMargin` 改为 **960 pt ≈ 339 mm**。

- 对已有行为**零影响**：`FitToWidth` 用的是页并集 `WorldBounds`（不含留白），页面的 fit 缩放与像素位置完全不变。
- `InkExtent` 随之变为 `2515 × 7957`（7 页试卷），其原点仍恒为 `(0,0)` ⇒ 零坐标补偿的前提不变。
- 代价要说清楚：**页宽适配时左右留白在屏幕外**，要写页外批注得先缩小或平移；竖直方向同理。

### 10.4 补丁后的 harness 变更

1. 新增 `RunFitWidthChecks`（4 组纯数学断言 + 1 组真实控件树断言）：
   打开落首页顶部 / Ctrl+0 保持中心 / 越界夹紧 / 小文档居中 / 首屏光栅确实是第 1 页顶部。
2. **M3 光栅断言的三组视口状态改为"页左上角落点"表达**（原来是裸的世界偏移数字）。
   旧写法隐含假设 `PageMargin = 96`，改留白后整页被推出视口，三条断言一起挂 ——
   这类"参数一变断言就静默失效"的写法本身就是缺陷，改掉。

### 10.6 页外空间改纯白（整纸观感）

**需求（用户原话）**：把页外的所有空间改成纯白色，整体就像一张纸一样。

**实现**：`CanvasViewportHost.xaml` 里 `RootGrid.Background` 由 `#2B2B29`（深灰）改为 `White`，一行。
底色层在**世界层之外**、不参与缩放；页面白矩形与 `InkCanvas`（`Transparent`）都在世界层之内，
所以"页外空间是什么颜色"只由这一处决定。另加 `CanvasViewportHost.CanvasBackground` 可写属性。

页面矩形那条 `0.6` world 单位的浅灰描边**保留** —— 底色与纸面同白之后，它是分辨页边界的唯一线索。

**为什么必须加那个属性（不是为了好看）**：原有两条光栅断言靠"白纸外接框"定位页面。
底色也是白之后，白像素会铺满整个视口、期望值也等于整个视口 —— **断言恒真、彻底失去区分度**。
所以把那两条改成在**黑底对照**下跑（harness 临时 `CanvasBackground = Black`，跑完立即切回白底）；
黑底只是验证手段，不是生产默认值。M3.5 的 `paperOnFirstScreen` 同理。

**新增 M3.6 断言（白底下的新需求）**：

| 断言 | 实测 |
|---|---|
| 全图扫描：页面之外**每个**像素都必须是纯白 | 页外 **516400** 个像素，零例外 |
| 三处页外采样均为纯白 | 页左留白(191,200) / 页右留白(809,200) / 页间缝隙(500,527) 全为 `rgb(255,255,255)` |
| 反向断言：页面内仍有非白像素 | 33697 个（防止"把整块画布涂白"也能全过） |

用**全图扫描**而不是抽点采样：采样只能证明"我挑的那几个地方是白的"，
而这条需求要的是"没有任何漏掉的深色区域"。扫描时对页面矩形向外豁免约 4 px：
页矩形有 0.6 world 单位描边、抗锯齿会向页外溢出，那不属于"页外空间的颜色"。

反向断言一开始写成"深色像素 > 5000"，实测只有 2264 —— `scale=0.5` 下笔画被抗锯齿拉成中灰，
卡深色阈值只是在标定常数。改成"页面内非白像素 > 1000"后与缩放无关。

**证据**：`artifacts/m36-smoke/paper-look.png`（缩放 0.5：页左右各露出 480 world 单位留白，
与纸面连成一片，看不出哪里是"页外"）。

## 11. 本机无法验证的三件事（一体机实测清单）

1. **湿墨（`DynamicRenderer`）的落位。** 笔尖落下到抬起的实时墨迹由 `InkPresenter` 的
   `DynamicRenderer` 绘制，与最终笔迹同一棵可视化树、理论上同变换，但 harness 伪造不了笔输入。
   - 判据：写字时墨在正确位置、抬笔后**不跳**。
   - 若出现"抬笔后跳一下"，说明湿墨没吃到祖先矩阵；备选是关掉 `DynamicRenderer`（牺牲实时感，但不会错位）。
2. **触摸是否真的不落墨。** 依赖 WPF 把触摸提升成 `TabletDeviceType.Touch` 的笔事件，本机没触摸屏。
   - 判据：手指在试卷上划 → 不出现墨；同时画布**应该**跟着平移/缩放。
   - 对账方法：看 `%LOCALAPPDATA%\MathPhys.Ink\logs\` 里的
     `stylus: type=... name="..." inverted=... → 抑制/落墨` 行（每种设备签名只记一次，最多 12 条）。
3. **笔尾反转是否被识别为 `Inverted`。** 本机没有笔。M3 只做"抑制"（反转笔不落墨），擦除是 M4。
   - 判据：笔尾按下去**不出墨**（若出墨，说明 `Inverted` 没被置位，M4 的橡皮方案要换路）。

## 12. 已知限制（明确接受，免得以后被当 bug 修）

1. **`scale > 6` 是位图拉伸**（继承 M2，瓦片渲染列 M9）。
2. **没有撤销**：写错了只能"清除笔迹"整片清空（M5）。
3. **笔迹不持久化**：换文档 / 关程序即丢（M6）。
4. **没有压感、笔尾不能擦**（M4）。
5. **可写范围有界**（= `InkExtent`）：页外 339 mm 之内能写，再远写不了。注意**页宽适配时左右留白在屏幕外**
   （页宽 + 2×留白 ≫ 视口宽），要写页外批注得先缩小或平移 —— 若实际用起来别扭，`DefaultPageMargin` 是一行参数。
6. **笔迹不参与页归属**：暂时做不到"只擦本页"（M4/M5 再引入）。
