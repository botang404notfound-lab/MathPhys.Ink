# M7.5 设计方案 —— GeoGebra 整合（重型几何动态演示插件）

> 状态：**方案已确认（2026-09-22）**，待实施。
> 前置：M7.4 全完成 ✅（回归 **429 PASS / 0 FAIL**，7 插件 12 工具 7 渲染器，交付包 77.3 MB）。
> 定位：把“白板上有一套学科工具集”再往前推一步 —— **能挂一个重型几何动态演示器（GeoGebra），
> 且不影响画布性能与一体机触控**。
> 铁律第四条（方案与文件改动清单确认后才写代码）已满足；本里程碑仍**逐步交付、每步一个测试包**。

## 1. 需求复述（我理解的样子）

你要的是：**在讲台上，能把“动起来”的几何/函数演示搬进白板**，而不是只能画静态图。

现在的白板已经有的（M7.4）：量角器、三角板、坐标系、函数图像、矢量箭头、合力、正交分解、矢量组 ——
这些是**自绘的轻量原生工具**，优点是与画布严丝合缝、随缩放平移同步、零外部依赖。
它们能覆盖“画一条函数曲线”这类需求，但覆盖不了：

| GeoGebra 才擅长的场景 | 原生自绘为什么不做 |
|---|---|
| 拖动一个点，整个图形**联动变形**（动态几何） | 要自建“约束求解器”，是另一个量级的工程 |
| 圆锥曲线、多边形、变换、轨迹 | 同上，且组合爆炸 |
| 现成的 **100 万+ 互动课件**直接用 | 自己画不现实 |
| 滑块调参数、动画播放 | 有基础设施（M7.4 参数面板）但远不如 GGB 成熟 |

所以本里程碑的目标是：**不重复造轮子，把 GeoGebra 这一“重型演示器”接进来**，
同时**不破坏**白板现有的架构不变量与一体机体验。

## 3. 为什么必须是“独立演示面板”（D-Geo-1 的完整论证）

### 3.1 原否决记录的三条理由，逐条复核

docs/11 §5.1 当初否决 WebView2，给了三条理由。选 A 之后逐条看：

| 原否决理由 | 选 A（独立面板）后的状态 |
|---|---|
| ① **触控穿透**：WebView2 独立进程消费笔/触摸，一体机“点不动/双击穿透” | ⚠️ **仍存在，但可控** —— 面板**不再叠在画布上**，两者是“并列/互斥”关系，不需要穿透。见 §5。 |
| ② **性能**：平移缩放跨进程同步 ⇒ 掉帧 | ✅ **消除** —— 面板不参与画布变换，画布平移缩放时**根本不需要通知它**。 |
| ③ **内容不参与 RenderTransform** | ✅ **消除** —— 我们**不再要求**它参与。GeoGebra 用自己的坐标系，这是它的天性，不是缺陷。 |

结论：**选 A 之后，原三条里两条直接消失、一条降级为“可管理的实现细节”。**
这不是“无视风险强行上马”，而是“改变定位使风险不再适用”。

### 3.2 ★ 必须写清楚的架构级硬约束：WPF × WebView2 的“空气空间”问题

**这一条决定了面板的形态，必须先讲明白。**

WebView2 在 WPF 里是**基于 HWND 的控件**（内部 HwndHost）。Windows 的窗口合成规则决定了：
**HWND 内容永远渲染在所有 WPF 视觉元素之上**，WPF 的 Visual 排版无法覆盖它。这就是经典的
**“airspace（空气空间）问题”**。

对我们的具体后果：

> **GeoGebra 面板一旦显示，它的矩形区域内，白板的墨迹层、图形对象层、预览层都“画不上去”。**

⇒ 所以**不能**做成“半透明浮层浮在卷面上、还能在它上面圈画”（那种形态在 WPF + WebView2 下**技术上做不到**，
不是“难做”）。
⇒ 面板形态必须是**与画布不重叠**的三种之一：

| 形态 | 说明 | 适用 |
|---|---|---|
| **A1. 停靠面板** | 画布缩小让出右侧/底部，GeoGebra 占一块 | 边讲边画、对照参考 |
| **A2. 独立窗口** | 另开一个 WPF Window 承载 WebView2 | 双屏/投影外接屏 |
| **A3. 全屏演示** ⭐ | 临时接管整个屏幕，退出后回到白板 | ★ **一体机主用法** —— 讲台上最需要“满屏看清楚” |

**推荐**：先做 **A3 全屏演示 + A1 停靠面板**两种形态（A2 独立窗口留给有外接屏的教室，P1 再说）。
理由：一体机屏幕就是唯一一块屏，全屏演示是“讲台刚需”；停靠面板是“参考刚需”。

### 3.3 术语约定（避免文档里混着叫）

- **画布**（canvas）= 白板主体：PDF 页 + 墨迹层 + 图形对象层，WorldHost 那套。
- **GeoGebra 面板**（panel）= 本里程碑新增的 WebView2 宿主区域。
- **两者是并列关系**：面板显示时，画布的墨迹输入被抑制（见 §5），不存在“同时在两个里写”。

## 4. 架构：WebView2 + 本地离线 Bundle

### 4.1 分层（沿用“契约 / 宿主 / 插件”三层，不动现有不变量的前提下加一层）

```
┌─ 宿主 MathPhys.Ink ────────────────────────────────┐
│  ┌─ 画布（现有，零改动）─────────────────┐               │
│  │  WorldHost（唯一 RenderTransform）     │               │
│  │  PdfPageLayer + GfxLayer + InkLayer    │               │
│  └────────────────────────────────────────┘               │
│                                                            │
│  ┌─ GeoGebra 面板（本里程碑新增）─────────┐               │
│  │  WebView2 宿主（HWND，不参与变换）      │               │
│  │    └─ 本地 index.html + GGB Bundle      │               │
│  └────────────────────────────────────────┘               │
│         ▲                                                  │
│         │ PostWebMessage / WebMessageReceived              │
│         ▼                                                  │
│  IGeoGebraBridge（宿主侧契约，新增）                       │
└────────────────────────────────────────────────────────────┘
        ▲
        │ 插件注册（走 M7.2 已有的插件宿主）
        │
┌─ Plugin.GeoGebra（新插件工程）──────────────────────────┐
│  GeoGebraPlugin : IPlugin                                │
│  GeoGebraTool   : ITool（一个“打开演示面板”的工具按钮）   │
└──────────────────────────────────────────────────────────┘
```

### 4.2 关键设计：**桥接契约放宿主侧，不放插件侧**

**为什么**：docs/06 的不变量说“契约只加新接口、ITool 成员零新增”。
WebView2 的宿主控件必须由 WPF 主窗口（宿主）来创建和管理（它需要挂在视觉树上、
需要处理 Window 生命周期），**插件没法自己 new 一个 WebView2 出来还能正确参与宿主布局**。

所以：

- **宿主侧**新增 IGeoGebraBridge（宿主提供，插件调用）：打开面板 / 关闭面板 / 发命令给 JS / 订阅 JS 消息。
- **插件侧** GeoGebraTool 只做一件事：点按钮 ⇒ context.GeoGebra?.Show(初始内容)。
- IToolContext **加一个可选属性** IGeoGebraBridge? GeoGebra（**加成员是加接口，不改已有成员** ——
  与“ITool 成员零新增”不冲突，因为加的是 IToolContext，且用 ? 可空 + 插件侧 is 判断兼容旧宿主）。

> ⚠️ **待实施时确认**：这是本方案**唯一**需要动宿主契约的地方。
> 实施前必须复核：加 IToolContext 成员会不会让**已分发的旧插件 dll** 出问题。
> 按现有约定（接口只加成员不删不改），旧插件**编译产物仍可加载**，只会“看不到新属性”。

### 4.3 离线：为什么必须用**本地 Bundle** 而不是 CDN

| 方案 | 结论 |
|---|---|
| CDN 加载 geogebra.org 的 deployggb.js | ❌ **不可用** —— 教室一体机可能没外网，且加载失败就是白屏 |
| **官方 Math Apps Bundle（离线包）** | ✅ **采用** —— 本地文件夹，SetVirtualHostNameToFolderMapping 映射后离线可用 |

**注意事项（实施时必做）**：

1. Bundle 解压后是 GeoGebra/HTML5/5.0/web3d/ 一类目录结构，**体积约 60~100 MB**，
   会让交付包从 77 MB 涨到 **140~180 MB** —— 这是可接受的（免安装包的代价）。
2. 必须用 **CoreWebView2.SetVirtualHostNameToFolderMapping** 把 Bundle 目录映射成一个
   虚拟域名（如 https://geogebra.local/），**不能用 file:// 直接开** ——
   file:// 下 GGB 的 WASM/Worker 会被同源策略拦掉，表现为“转圈不出图”。
3. webView.CoreWebView2.Settings 需按需关掉 AreDevToolsEnabled（讲台上不需要）。
4. 背景色：如果做成 A1 停靠面板，设 DefaultBackgroundColor = Colors.White（**不要透明** ——
   透明会让 HWND 区域出现黑边/闪烁）。

### 4.4 ★ WebView2 Runtime 的“免安装”问题（本里程碑最大的交付风险）

WebView2 控件**依赖运行时**（WebView2 Runtime）。它在 Win11 和多数已更新的 Win10 上**预装**，
但**希沃一体机的 Win10 不一定有**。而我们项目的铁律是**“凡需要测试一律打包成免安装测试包”**。

| 方案 | 体积代价 | 结论 |
|---|---|---|
| **① 依赖系统运行时 + 启动自检** | 0 MB | ⚠️ 若一体机没有 ⇒ 直接开不了 |
| **② 打包 Fixed Version Runtime** | **+130~180 MB** | ✅ **推荐** —— 真免安装，与项目铁律一致 |
| ③ Evergreen Bootstrapper 联网装 | 需外网 | ❌ 教室可能没网 |

**推荐 ②**：Microsoft.Web.WebView2 的 **Fixed Version** 分发模式，把运行时一起放进 dist/tablet/webview2/，
用 CoreWebView2Environment.CreateAsync(browserExecutableFolder: ...) 指定固定路径。
**同时保留启动自检**：检测不到就给出**中文可读提示**（不是崩溃），并回退到“面板不可用、其它工具照常”。

> ⚠️ **待实施时确认**：Fixed Version 的具体目录名与 API 参数，装 NuGet 后按实际版本核对。
> 本条**不阻塞方案**，但**必须在打包前实测一次**“在一台没有 WebView2 的机器上能否启动”。

## 5. 触控事件路由（一体机焦点冲突）

### 5.1 问题本质

希沃一体机的输入源有：**红外触摸框**（手/笔）、**电磁笔**（部分机型）。当屏幕上同时存在
“WPF 画布”和“WebView2 面板”两个可交互区域时，有三个具体风险：

| 风险 | 表现 | 对策 |
|---|---|---|
| **R1 焦点争抢** | 点面板时，宿主窗口仍抢到笔事件 ⇒ 卷面上留下墨点 | 面板激活时**抑制画布墨迹输入** |
| **R2 触摸穿透** | 在面板上滑动，画布跟着平移 | 面板是 HWND，天然不穿透；**但要确认面板未激活时的降级行为** |
| **R3 笔尾橡皮** | M4.2 的希沃笔尾反转信号可能被 WebView2 吞掉 | 面板激活时**禁用笔尾擦除**，退出面板后恢复 |

### 5.2 对策：**互斥激活**（不是“共存”，是“切换”）

```
画布模式（默认）                      面板模式（打开 GeoGebra 后）
─────────────────────                ─────────────────────
墨迹层 IsHitTestVisible = true        墨迹层 IsHitTestVisible = false   ← 关键
工具按键可用                          工具按键置灰（或仅“选择”可用）
笔尾擦除启用                          笔尾擦除禁用
视口手势（双指/空格平移）可用          视口手势禁用（避免与 GGB 的平移冲突）
```

**核心一行**：面板显示 ⇒ InkLayer.IsHitTestVisible = false（与 M7 里“选中非落墨工具时的处理”同一条路子）。
**退出面板 ⇒ 恢复原状态**（必须记下进入前的状态，不能一律恢复成 true）。

### 5.3 显式的前台开关（不靠猜焦点）

**不要**依赖“窗口焦点自动切换”来判断用户在哪个区域操作 —— 一体机的红外框焦点行为不可靠
（M4.2 已经吃过这个亏）。做法：

- 面板打开 = **显式进入“面板模式”**，宿主状态机明确切换，不依赖 GotFocus/LostFocus。
- 面板上提供一个**醒目的“返回白板”按钮**（大目标，触摸友好，≥ 48 DIP），
  以及快捷键（如 Esc）退出。
- 退出时若 GGB 里改过东西 ⇒ 询问“是否把当前图形导出为图片贴到卷面”。**这个可后置（P1）**，
  P0 先做“退出即关闭，不保留”。

### 5.4 面板形态与触控的关系

- **A3 全屏演示**：面板占满屏幕 ⇒ 不存在“两个区域”，R1/R2 天然消失，只剩 R3（禁用笔尾擦除解决）。**最稳**。
- **A1 停靠面板**：面板与画布并列 ⇒ 必须做 5.2 的互斥激活。
  **建议 P0 先只做 A3**（风险最低），A1 放到 P1 验证过触控后再加。

## 6. 通信契约：PostWebMessage ↔ postMessage 双向

### 6.1 通道选型

WebView2 提供两条通道：

| 通道 | 方向 | API | 结论 |
|---|---|---|---|
| **宿主 → JS** | 单向 | CoreWebView2.PostWebMessageAsJson / PostWebMessageAsString | ✅ 用这个 |
| **JS → 宿主** | 单向 | JS window.chrome.webview.postMessage(obj) → C# WebMessageReceived 事件 | ✅ 用这个 |
| 宿主主动求值 | 同步返回 | ExecuteScriptAsync(js) | ⚠️ 只在“必须拿返回值”时用（异步、易超时） |

**原则**：**默认用消息（事件驱动、不阻塞）；只有“必须立刻拿一个值”时才用 ExecuteScriptAsync。**

### 6.2 消息格式约定（**必须固定，否则两边各写各的**）

统一信封，**永远是 JSON 对象，带 type 字段**：

```jsonc
// 宿主 → JS
{ "type": "loadMaterial", "payload": { "ggbBase64": "...", "mode": "geometry" } }
{ "type": "command",      "payload": { "label": "A", "action": "setCoords", "value": [1, 2] } }
{ "type": "reset" }

// JS → 宿主
{ "type": "ready",     "payload": { "version": "5.0.x" } }       // GGB 初始化完成
{ "type": "changed",   "payload": { "objects": [ /* ... */ ] } }  // 图形变了（可选，节流上报）
{ "type": "error",     "payload": { "message": "..." } }
{ "type": "exportPng", "payload": { "dataUrl": "data:image/png;base64,..." } }
```

**约定细节**：

1. **ready 必须先到**：宿主收到 ready 之前**不发任何命令**（否则命令发给一个还没建好的 GGB，静默丢失）。
   ⇒ 宿主侧要有一个“就绪闸门”（TaskCompletionSource 或状态位）。
2. **type 一律小驼峰英文**，payload 里可以放中文。
3. **changed 必须节流**（≥ 200 ms 合并一次）—— GGB 拖一个点时消息会很密，不节流会拖慢面板。
4. **所有消息处理必须 try/catch**：JS 侧异常要回 error 消息，**不要在 JS 里静默失败**
   （否则现场表现是“点了没反应”，无法排查 —— 这是本项目的老教训）。

### 6.3 C# 侧契约草图（实施时细化）

```csharp
// 宿主侧新增（契约层）
public interface IGeoGebraBridge
{
    bool IsAvailable { get; }                        // WebView2 运行时是否就绪
    bool IsOpen { get; }                             // 面板是否已打开
    Task ShowAsync(string? materialBase64 = null);   // 打开面板（A3 全屏 / A1 停靠）
    Task HideAsync();                                // 关闭并恢复画布输入
    Task SendAsync(string type, object? payload);     // 宿主 → JS
    event EventHandler<GeoGebraMessage>? MessageReceived;  // JS → 宿主
}
```

> 命名与签名**实施前再定稿**，此处只固定“能力边界”，不固定 C# 细节。

## 7. 离线包目录约定

```
dist/tablet/
├─ MathPhys.Ink.exe
├─ plugins/
│  └─ geogebra/
│     └─ geogebra.dll                 ← 本里程碑新增插件
├─ webview2/                          ← ★ Fixed Version Runtime（免安装关键）
│  └─ <版本号>/ ...                    （约 130~180 MB）
└─ geogebra/                          ← ★ 官方 Math Apps Bundle（离线）
   ├─ index.html                      ← 我们自己写的宿主页（桥接脚本在这）
   ├─ bridge.js                       ← postMessage 封装
   └─ HTML5/5.0/web3d/...              （官方 Bundle 原样）
```

**约定**：

- **官方 Bundle 原样放入，不改它的文件**（改了就说不清“我们用的是不是官方包”）。
- **我们自己的代码只有 index.html + bridge.js**（几十行），与 Bundle 分离，便于升级 Bundle。
- 升级 Bundle = **整体替换 geogebra/HTML5/ 目录**，不动 index.html（除非 API 变了）。
- 目录缺失时：面板按钮**置灰 + 中文提示**（“GeoGebra 资源未部署，请重新解压完整包”），**不崩**。

## 8. 许可与署名（D-Geo-3 的落地）

### 8.1 许可事实（**已核实官方页面**，2026-09-22）

GeoGebra 是**分层许可**，不同组成部分走不同协议：

| 组成部分 | 许可 | 是否约束我们 |
|---|---|---|
| **源代码** | 新版 **EUPL 1.2**（旧版页面曾写 GPL v3） | ❌ 我们不读它源码、不编译它源码 |
| **安装包 / Math Apps Bundle 离线包** | **GeoGebra 自有条款：仅限非商业 + 必须署名** | ★ **约束我们的是这条** |
| 语言文件 / 图标 / 样式表 | CC BY-NC-SA 3.0/4.0 | ✅ 非商业即合规 |

**★ 一个重要的澄清**（原需求的表述需要更正）：

> 需求里写“源码为 GPL v3，但官方许可仅限非商业用途”。
> 精确说法是：**“仅限非商业”这条限制来自“安装包/资源/服务”的条款，不是 GPL 的附加条款**。
>

> **① 署名 GeoGebra；② 不用于商业用途。**

## 9. 与原生工具的边界（“什么时候用 GeoGebra”）

**需求原文**：“如果某个工具用 GeoGebra 实现成本远低于原生，优先调 GeoGebra；否则保持原生实现。”

**我的落实建议**（把它变成一条**可执行的判据**，而不是一句口号）：

> **判据：这个工具需要“联动求解 / 约束变化 / 动画”吗？**
> - **需要** ⇒ 交给 GeoGebra（自己写约束求解器是另一个量级的工程）
> - **不需要**（一次性画出来就不变的） ⇒ **保持原生自绘**

按这个判据复核现有与近期工具：

| 工具 | 归谁 | 理由 |
|---|---|---|
| 直尺 / 量角器 / 三角板 | **原生**（已完成） | 静态量具，无联动 |
| 坐标系 + 函数图像 | **原生**（已完成） | 采样画线即可，无约束求解需求 |
| 矢量箭头 / 合力 / 正交分解 / 矢量组 | **原生**（已完成） | 矢量和是四则运算，不需要 GGB |
| **动态几何演示**（拖动点、图形联动变形、轨迹） | **GeoGebra** | ★ 典型的“约束求解”需求 |
| **圆锥曲线 / 多边形 / 变换** | **GeoGebra** | 组合爆炸，自绘成本极高 |
| **现成互动课件演示**（GGB 素材直接打开） | **GeoGebra** | 100 万+ 素材是它的核心价值 |

**明确不做的**（避免“什么都想塞进 GGB”）：

- ❌ 不把已有的 6 个原生工具重写成 GGB 版（已交付、已验证、体验好，重写是纯浪费）。
- ❌ 不做“GeoGebra 图形回写到卷面变成可编辑对象”（那需要解析 GGB 内部模型，
  **P1 之后再说**；P0 最多做到“导出 PNG 贴上去”）。
- ❌ 不做“GGB 与原生坐标系双向绑定”（两套坐标系同步是坑，且与选 A 的定位矛盾）。

**关于 OxyPlot 的措辞澄清**：
需求写“不替代 OxyPlot 等轻量原生方案”。项目实际情况是：**docs/11 §5.1 从未引入 OxyPlot**，
函数图像是**自绘**的（StreamGeometry，约 100 行）。所以这条需求的**实质意思**我们照做：
**“有了 GeoGebra 也不放弃轻量自绘方案”** —— 函数图像**继续保持自绘**，不改成 GGB。
（文档侧已在 §5.1 交叉引用说明，避免“以为项目里有 OxyPlot”这个误解。）

## 10. 已预见的坑（提前写下来，省一轮返工）

### 10.1 空气空间（airspace）—— 已升格为架构约束

见 §3.2。**一句话**：WebView2 是 HWND，永远在 WPF 之上，
**别设计“半透明浮层 + 在上面写字”的形态**（做不到，不是难做）。

### 10.2 file:// 打不开 Bundle

必须 SetVirtualHostNameToFolderMapping 起一个虚拟域名。
直接 Navigate("file:///...") 会因同源策略导致 WASM/Worker 加载失败 ⇒ 白屏转圈。

### 10.3 ready 之前发命令 = 静默丢失

宿主侧必须有就绪闸门。**没有这道闸门的表现是“偶发点了没反应”**（依赖加载时序），
现场极难复现 ⇒ 一定要做闸门，不要靠“等一下就好了”。

### 10.4 WebView2 运行时缺失 = 白板整体打不开？

**绝不能**。面板必须**失败隔离**：运行时缺失 ⇒ 面板按钮置灰 + 提示，**白板本体照常可用**。
（这正是 M7.2 插件“失败隔离”原则的延续。）

### 10.5 包体积翻倍

77 MB → 140~180 MB（Bundle 60~100 MB + Fixed Runtime 130~180 MB，压缩后约翻倍）。
**这是免安装的必然代价**，接受。但要在“怎么测试.txt”里说明“包变大了是正常的”。

### 10.6 触控：别依赖焦点自动切换

见 §5.3。一体机红外框的焦点行为不可靠，**一律用显式状态机**。

### 10.7 内存

GGB 是重型 Web 应用，启动后常驻内存可能 **200~400 MB**。
⇒ **面板关闭时应彻底释放**（WebView2.Dispose()），不要留着隐形占内存。
⇒ 一体机内存有限，这条要实测。

### 10.8 别在 JS 里静默失败

见 §6.2 第 4 条。所有 JS 异常都要回 error 消息 + 宿主侧记日志。

### 15.3 本次踩到的四个坑（都已写进代码/脚本注释）

1. ★★ **插件 dll 不会被 `build` / `publish` 自动铺到 `plugins\`**（插件不在宿主引用图里）。
   症状：**按钮根本没出现、面板句柄 = 0**，日志里只有一行"面板可用"，极易误判成"WebView2 装不上"。
   ⇒ 产出可复用脚本 **`tools/_stage_plugins.py`**（清空插件子目录 → 复制 → 回读校验）。
2. ★★ **抓图前必须先声明 DPI 感知**（`shcore.SetProcessDpiAwareness(2)`）。
   不声明的话 Windows 把 2560×1440 的屏报成 1707×960，`GetWindowRect` 只返回左上角那"一块"，
   于是抓图里**标题画出来了、同一行的按钮不见了** —— 症状与"界面缺陷"完全一样，**本次为此白查了一轮**。
   识破它的线索：顶栏实测 **102 px** 而布局日志说 **68 DIP**，`102/68 = 1.5` 才露出显示缩放的马脚。
3. ★ **整屏 `ImageGrab` 在锁屏／无人值守下只能拍到登录界面**（大时钟 + 小组件，无任务栏）。
   ⇒ 一律改为按句柄抓：`PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)`，且抓之前 `RedrawWindow` 强制重绘一次。
4. ★ **`Window` 不 `Show()` 时，它的内容没有 `PresentationSource`**，`Measure/Arrange` 量下来全是 **0**。
   harness 里要量布局，必须把 `Content` 从 Window 上摘下来单独量（`DockPanel` 的布局规则自洽，
   数字与真开窗一致 —— 真机日志里的 `200×48 @ (1493,10)` 就是佐证）；
   且**判 `Visibility` 而不是 `IsVisible`**：脱挂后 `IsVisible` 恒为 `false`，拿它当判据会得到一条永远红的**假断言**。

另有一条设计上的改判：原本打算用 `SetInkHitTestVisible(bool)` 控制画布输入，后改为
`EnterPanelMode()` / `ExitPanelMode()` 两个动词 —— 因为 `Set(bool)` 会在"退出时按进入前的值又调 `Set(false)`"
这条路径上写出**死锁**（白板永久写不出字）。退出 = **把决定权还给当前工具**。
