## 1. S1 顶部工具隐藏（沉浸模式）

### 1.1 现状勘察
- `MainWindow.xaml`：顶部是一个 `Border DockPanel.Dock="Top"`（ChromeBar 样式），内含两行；**没有 x:Name**，当前无法从代码隐藏。
- 右上角 `ThemeButton` / `WindowModeButton` 用 `Dock=Right` 常驻，注释明确写着「全屏时没有标题栏，它们是老师唯一的退路，绝不能被挤到看不见」。
- 界面状态持久化走 `UiStateStore`（键值文本、读-改-写、失败吞掉），已有 `fullscreen` / `theme` 两个键的先例。

### 1.2 设计方案
**行为定义**
1. `F9`（或悬浮球入口，S2 后）在「显示 / 隐藏工具栏」间切换；隐藏 = 顶部 Border `Visibility.Collapsed`，画布占满整个窗口（状态栏一并隐藏，只留画布）。
2. **唤出手段（隐藏态下）三选一兜底**：
   - **上边缘轻触/悬停**：窗口顶部留一条 **12 DIP 高的透明唤出条**（鼠标进入即显示；触摸为点按）。显示后工具栏处于「临时态」，点画布或 4 秒无操作自动再隐藏；
   - `F9` 再按一次恢复常显；
   - S2 落地后，悬浮球成为主要入口。
3. 隐藏状态记入 `UiStateStore`（新键 `toolbar_hidden`，沿用读-改-写惯例，写失败不影响使用）。启动时恢复上次状态，但**首次隐藏给一条一次性的状态栏提示**（「按 F9 或点屏幕顶部可唤出工具栏」），防老师在一体机上「工具栏丢了」。

**两个必须先想清楚的点**
- ★ **隐藏不得改变缩放**。M8 S2 的教训：`CanvasViewportHost` 尺寸变化会触发 SizeChanged，若 `_autoFitWidth` 还在，缩放会被重算（存档视口被算掉的同源问题）。适应宽度模式按宽度适配，工具栏只占高度，理论上 scale 不变，但**必须作为 harness 断言钉死**（隐藏前后 scale 与视口偏移逐位相等），不能靠「理论上」。
- ★ **右上角两颗常驻按钮随栏一起藏** —— 这是对 M10 注释里「绝不能看不见」的一次**有意修订**：隐藏态下退路改为「上边缘唤出条 + F9 + 悬浮球」，三者任一都独立可用。S1 阶段（还没有球）先落前两个；这是本步最大的设计取舍，需要用户点头。

## 2. S2 悬浮球系统

### 2.1 现状勘察
- M10 惯例：纯代码建 UI 的文件已有多处（`GfxParameterPanelView.cs`），走 `Design/Tokens.cs` 取令牌；图标全部自绘于 `Design/Icons.xaml`（24 网格）。
- 触控可用性红线：`Spacing.xaml` 里 `Touch.Min=40`（最小可按 40 DIP）。
- 主窗口内容区 = `Grid`（画布 + GeoGebra 停靠区两列），悬浮球可挂在 `Grid.Column=0` 之上（不进 `WorldHost`，**绝不随世界缩放/平移**）。

### 2.2 设计方案
**形态**
- 默认吸附在画布**右缘垂直居中**的 48 DIP 半透明圆钮；可沿右缘垂直拖动（`ManipulationDelta` 通吃触摸与鼠标），松手后贴边。位置记 `UiStateStore`（`ball_y`）。
- **单击展开扇形子菜单**（不再拖动时），子项 ≥40 DIP；再点空白处收起。子菜单项从**命令总线**取（见 §5.0），M12 初版内置：
  - 唤出/隐藏工具栏（S1 的主入口）
  - 工具三快切：笔 / 橡皮 / 选择（后续跟随模式配置增减）
  - 撤销、翻页（上一页/下一页）
- 显示策略三档：`auto`（工具栏隐藏时出现，默认）/ `always` / `off`，记 `UiStateStore`。

**输入归属（本项目最敏感的雷区）**
- 悬浮球是**画布之上的独立元素**：命中测试天然先于 InkLayer，球上的触摸不会落墨——这是 WPF 元素树的既有语义，不需要写代码拦截，但**必须有真机冒烟证明**（球上拖一笔 ⇒ 笔迹条数不变）。
- GeoGebra 停靠区展开时球自动避让（停靠区是 `Grid.Column=1`，球挂在 Column 0 内，布局天然隔离；展开时若球被压缩区域覆盖，重新贴右缘即可）。

## 3. S3 图层系统 V1（批注层 / 草稿层）

### 3.1 现状勘察与核心决策
- 全部笔迹在一个 `InkSurfaceCanvas`（`InkLayer`），`InkLayer` 本地坐标 ≡ 世界坐标（不变量，不能动）。
- 持久化 = ISF（`.tbink` / `.twb` 内的 `annotation.tbink`），M11 笔锋已经证明 **`StylusPoint`/`Stroke` 的标准属性能被 ISF 原生带走**。
- `InkHistory` 靠 `StrokesChanged` 反做撤销；`BoardHistory` 把墨迹步与图形步排成统一时间线。

**★ 核心决策：图层 = 每条 Stroke 的自定义属性数据（`AddPropertyData`），不是多集合、不是多 InkCanvas。**
- 一个 Guid 属性 `MathPhys.LayerId` 写进 `DrawingAttributes`，**ISF 原生序列化** ⇒ `.tbink` / `.twb` 格式**零改动**、旧文件读入默认归「批注层」（属性缺席 = 批注层 = 现状），完全向后兼容。
- 渲染层不拆：WPF 的 `InkCanvas` 只渲染 `Strokes` 集合里的内容。**隐藏图层 = 把该层笔画移进一个旁路 `StrokeCollection`（不渲染）**。移动会触发 `StrokesChanged` ⇒ 必须抑制撤销记录，否则「隐藏草稿层」会变成一步可撤销的「删除」。
  - 方案：`InkHistory` 加一个**抑制作用域**（`BeginSuppress()/EndSuppress()`，模仿现有 `_applying` 内部守卫的公开版）。「隐藏/显示」不可撤销；**「清空草稿层」保持可撤销**（它就是一次真实的 remove，走正常记录）。
- 橡皮在可见笔画上照常工作（被移走的笔画不在 `Strokes` 里，天然擦不到）——行为正确，写进验收。

### 3.2 设计方案
**V1 只做两个固定层**（不做任意多层——讲评课的真实诉求是「草稿可以整体藏/整体删，正式批注永远在」，两层刚好表达）：
- **批注层**（默认）：讲评正式笔迹，导出必含。
- **草稿层**：演算、试画、比划。可整体隐藏/显示、一键清空（可撤销）。
- 新笔归入「当前层」，工具栏与悬浮球各给一个两档切换（默认批注层）。
- 图层弹出面板：两个可见性眼睛 + 「当前层」选择 + 清空草稿。入口：工具栏 + 悬浮球菜单。
- 导出语义（要向用户挑明）：**导出所见**——草稿层隐藏时导出的 PNG/PDF 不含草稿。这是特性不是缺陷（给学生发干净版、自己留带草稿版），写进操作卡。

## 4. S4 题号导航与错题标记

### 4.1 现状勘察与关键约束
- PDF 只有栅格化页面，**没有题目文本坐标** ⇒ 题号位置只能由老师标注产生，程序无法自动识别（这点要先跟用户对齐预期）。
- 图形对象的持久化：`.twb` 走 `GfxObjectStore.Snapshot()/Restore()`；**快速模式（.tbink 侧车）下图形对象是否随存、存哪，本轮未查证**——见前置勘察项。
- 跳页复原视口必须走 `RestoreView`（M8 S2 教训：直接 `SetView` 不触发 `ViewportMutated`，存档白存）。

### 4.2 设计方案（两条实现路线，推荐 A）
- **路线 A（推荐）：题号标记 = 一种宿主侧图形对象**
  - 新增宿主内置 Kind `questionMark`（渲染器注册进 `GfxRendererCatalog`，与插件渲染器同待遇）：数据 = 页内世界坐标锚点 + 题号文本 + 状态（`未讲 / 错题 / 已讲评` 三态循环）。
  - 好处：**Z 序、命中测试、选中拖动、Snapshot/Restore 持久化、渲染器异常隔离全部白得**；`.twb` 持久化零改动。
  - 标记点击（单选状态下双击）→ `RestoreView` 跳到该题所在页与位置。
  - 错题状态用颜色区分（红圈 = 错题、绿勾 = 已讲评），**会进导出**（讲评版自然带走标记；若要「干净版」，隐藏标记层即可——复用 S3 的图层开关思路，标记对象支持整体隐藏）。
- **路线 B：独立 `Marks/` 子系统 + `.twb` 新增 `marks.json` 载荷** —— 格式与校验都要动 `TwbFile/manifest/integrity`，成本明显更高，只有当「标记不能算图形对象」有硬理由时才值得。没有。

**交互**
- 工具栏/悬浮球「题号标记」进入标注模式（创建型工具惯例：落成自动弹回选择）→ 在题目旁点一下 → 弹小键盘输入题号（复用 FunctionPlot 的 `VirtualKeyboard` 惯例）。
- 导航：「上一题/下一题」按**当前页内题号排序**跳转；跨页顺延。侧边不缩略图（V1 不做页面缩略图栏，成本高收益低）。

### 4.3 前置勘察项（S4 动工前必须查清）
1. 快速模式（.tbink 侧车）下图形对象是否持久化？若否，「打开 PDF 顺手标几题」的场景会丢标记 ⇒ 需要给侧车补图形段或明确声明「标记仅工程模式可用」。
2. 宿主侧 Kind 注册进 `GfxRendererCatalog` 的既有口子（`RegisterGfxRenderer` 已存在，确认宿主 Kind 的数据反序列化路径）。

## 5. S5 模式化工作台与自定义宏

### 5.0 架构前置：命令总线（建议并入 S2 做）
现在「一个动作 = 一个 Click 处理方法」散在 `MainWindow.xaml.cs`。悬浮球、宏、模式三件事全都要**以编程方式触发同一批动作**。若不做总线，悬浮球只能反射调私有方法，宏更是无从下手。
- 新增 `Workflows/CommandBus.cs`：`Register(id, Action)` + `Execute(id)` + `Ids` 枚举；MainWindow 启动时把现有按钮动作登记成命令（按钮 Click 改调总线，行为一字不变——这一步独立提交、独立回归，是纯重构步）。
- 悬浮球菜单、宏、模式、S6 回放入口全部只消费命令 id。

### 5.1 模式（工作台预设）
- **V1 三模式**：`批改`（= 现状默认）/ `讲评`（默认红笔、草稿层自动开、题号导航按钮前置）/ `演示`（工具栏隐藏、悬浮球 always、墨色只留 2 色）。
- 模式 = 一份 JSON 预设文件（`%LOCALAPPDATA%\MathPhys.Ink\modes\讲评.json`），内容 = 命令序列（应用一个模式 = 按顺序 Execute 一串命令 id）⇒ **模式就是内置宏**，只做一套机制。
- 切换入口：悬浮球菜单 + 工具栏下拉；当前模式记 `UiStateStore`。模式切换**不弹窗、不阻断**，状态栏一句提示。

### 5.2 自定义宏
- 宏文件 `%LOCALAPPDATA%\MathPhys.Ink\macros.txt`：一行一个，`名称=命令id;命令id;…`，记事本可编辑（延续 ui-state 的「人能读、坏了不影响启动」哲学）。V1 **不做宏录制 UI**（录 UI 是大坑，文本定义对个人工具够用）。
- 触发：悬浮球菜单列出全部宏 + 可选热键（文件里可写 `Ctrl+Shift+1=名称`）。
- 执行失败（命令 id 认不出）＝ 跳过并日志 WARN，绝不中断宏串（不静默：状态栏提示哪条没执行）。

## 6. S6 笔迹回放 / 录屏

### 6.1 结论先行
- **录屏：不做。** Windows.Graphics.Capture / Media Foundation 编码是另一个量级的工程（编码器、格式、权限、性能），且系统自带 `Win+G`（Xbox Game Bar）在一体机上可用。把它塞进白板违背「一次只做一个小功能」。写进操作卡教老师用系统录屏即可。
- **回放：做，但 V1 只限本次会话**。理由：回放需要「操作 + 时间戳」序列；M11 的 `InkSampleBuffer` 有逐点时间戳但**不持久化**；要跨次回放就得给 `.twb` 加新载荷（格式、校验、兼容三连）——收益配不上成本。讲评课的真实场景是「这页讲完马上重放一遍给全班看」，会话内回放已覆盖。

### 6.2 设计方案
- `Ink/ReplayRecorder.cs`：订阅 `StrokesChanged`（含图形对象的 `Changed`？V1 只回放墨迹，图形不回放——明确声明），记录 `(时间戳, Added[], Removed[])` 步序列，内存上限按条数截断（防一节课撑爆内存）。
- 回放器：按步施加（复用 `InkHistory` 同一套「反做/正做」语义的**正做**方向）；步进模式（点一下进一步）+ 自动播放（DispatcherTimer，步间隔可调）；回放期间 `InkInputPolicy` 锁输入、锁撤销；Esc / 点「结束」退出并**原样恢复现场**（先记下当前全量快照，回放结束整体还原）。
- 入口：悬浮球「回放本页」——只回放**当前页可见的笔画**（按层与页过滤），跨页回放 V1 不做。

## 7. S7 智能吸附与函数参数联动（优先级最低，先给可行性结论）

### 7.1 智能吸附（矢量箭头吸到坐标系格点）
- 基础设施已就位：`BoardQuery`（`IBoardQuery`）就是插件间查询口；吸附半径是「世界长常量进屏幕语义」⇒ **必须除 `Scale`**（不变量，已踩三次的同族雷）。
- 需要「谁能提供吸附目标」的查询口：按契约纪律**只加新接口**——`Abstractions` 增加可选接口 `ISnapTargetProvider`（返回格点/轴的世界坐标集合），CoordSystem 插件实例实现；VectorArrow 的 `ArrowTool` 拖动时 `is ISnapTargetProvider` 探测（**必须实例实现、`is` 判断**，不变量原文）。`ITool` 成员零新增，旧插件零影响。
- 吸附视觉反馈画在 `ToolPreviewLayer`（临时视觉的既有归属，不进撤销栈）。
- 倾向：**做，但排在所有高优项之后**；文件清单（`Abstractions/ISnapTargetProvider.cs` 新增、CoordSystem 插件实现、VectorArrow 插件改造、harness）等轮到它时再细化。

### 7.2 函数参数联动（拖曲线改参数）
- 全部工作在 FunctionPlot 插件内（`FunctionTool/FunctionRenderer/GfxParameterCoordinator`）。拖动曲线 = 整体平移，反解 `a/b/c` 只对 `y=ax+b`、`y=a(x-h)²+k` 这类**平移可解**的形式成立；一般曲线（三角、指数）无法从平移反解参数。
- 倾向：**V1 只做「一次函数与二次函数的平移反解」**，其余函数拖动仅平移不反解（行为明确声明）。待 S1~S6 落定后单独立项。

### 10.2 S7 的三个关键决策（细节见 docs/06 §16）

1. **函数曲线 y 翻转修复**：曲线 Path 曾把数学 y 直接当本地 y（无翻转），而网格/特征点标注/输入窗预览三处都是「本地 y = −数学 y」⇒ 曲线相对网格整条上下镜像（既有 bug，e2e 像素断言对翻转不敏感所以从未抓到）。修复收在**渲染出口**（`FunctionRenderer.CreateVisual` 的 `FlipToLocal`），不动采样器（它还喂输入窗预览，改采样器会双重翻转）。rebase 同口径 `mdy = −localDelta.Y`。
2. **rebase 只对「绑定坐标系」的曲线生效**（store 的 bind 分支才走折算；自由曲线拖位姿本来就是对的设计）。增量口径：选择工具每帧传**绝对中心** ⇒ `BeginRebaseDrag` 复位锚点 = 对象中心，换对象当场重起算。
3. **视觉重建判据补 ContentVersion**：函数平移折算只改 h/k 参数、窗口尺寸不变，`GfxObjectLayer.Sync` 原本只认 LocalSize ⇒ 曲线永不重画。宿主内部版本号，零契约改动。
