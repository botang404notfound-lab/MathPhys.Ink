# M6 设计方案：批注持久化

> 目标：批注能落盘、能自动恢复。关掉程序再打开，画过的还都在。
>
> 前置：M0~M5 全部完成并验收通过（工具链 / PDF 导入 / 视口与渲染 / 笔迹层 / 笔与橡皮 / 撤销重做）。

---

## 1. 一句话设计

**批注存成试卷旁边的同名侧车文件 `<试卷名>.pdf.tbink`，格式是「自描述头 + manifest JSON + ISF 笔迹」；
停止书写 2 秒自动落盘，切文档/关窗口强制落盘，另有 Ctrl+S。**

---

## 2. 四个关键决策与理由

### 2.1 存哪里：侧车文件，不集中存

```
26西附全真模拟1物理试卷.pdf          ← 试卷
26西附全真模拟1物理试卷.pdf.tbink    ← 批注（紧挨着）
```

理由只有一个，但足够硬：**试卷要拷到一体机上去用**。

- 侧车方案：拷走 PDF 时把同名 `.tbink` 一起选上，批注就跟着走了；
- 集中存 `%LOCALAPPDATA%` 方案：换台机器就找不到批注了，还得额外拷一份数据目录，且要处理路径/指纹映射。

**故意不做成隐藏文件**：看得见它，才知道要连它一起拷。

### 2.2 文件格式：不写裸 ISF，包一层容器

```
偏移      内容
[0..6)    魔数 "TBINK\0"
[6..8)    格式版本 u16
[8..12)   manifest 长度 i32（UTF-8 字节数）
[12..)    manifest JSON
[...]     ISF 笔迹字节（StrokeCollection.Save 的原始输出）
```

**为什么不直接用裸 ISF**：ISF 里只有笔迹本身，没有"这条笔迹属于哪份 PDF、页面排在哪"。
一旦它被配到另一份试卷上，笔迹会**静默错位到别的题上** —— 界面上看就是"批注自己跑偏了"，
几乎无法追查。包一层 manifest 才有判断依据。

manifest 记录：

| 字段 | 用途 |
|---|---|
| `SourceFingerprint` | 内容指纹，判断"是不是同一份 PDF" |
| `Pages[]` | 各页在世界坐标中的矩形，判断排版是否一致、是否需要平移补偿 |
| `PageMargin` / `PageGap` | 排版参数，便于诊断 |
| `SourceFileName` / `SourceLength` | 诊断用 |
| `CreatedUtc` / `UpdatedUtc` | 重新保存时沿用创建时间，能看出这份批注从什么时候开始写 |
| `StrokeCount` | 诊断用（以 ISF 载荷为准） |

**JSON 刻意放在 ISF 之前**：用记事本打开这个文件，开头就是一段可读的元信息，
排查"这份批注是哪来的、对不对得上"时不必再写工具。

**读取一律走 `TryRead` 而不抛异常**：批注文件可能被外部工具改坏、或来自更高版本的程序，
这些都属于**预期内的正常情况**，应当优雅拒绝而不是崩掉。

### 2.3 加载判定：四层，从"绝不静默出错"倒推

| 判定 | 情况 | 处置 |
|---|---|---|
| ① 页数 | 批注 N 页 vs 当前 M 页 | 不等 ⇒ **拒绝** |
| ② 逐页尺寸 | 容差 0.5 world | 不等 ⇒ **拒绝** |
| ③ 整体偏移 | 各页偏移是否一致 | 一致 ⇒ **平移补偿后加载**；不一致（页间距变了）⇒ **拒绝** |
| ④ 内容指纹 | 32 位十六进制 | 相同 ⇒ 干净加载；不同 ⇒ **加载 + 黄字警告** |

设计取向：**排在第一优先的是"绝不静默把批注错位"**，第二优先才是"尽量让用户看到批注"。
所以①②③一律拒绝，只有④（几何完全对得上、只是文件内容变了）才放宽为"加载但提醒"。

④ 之所以放宽，是因为"重新下载了一遍同一份试卷"在实际使用中比"同名文件被覆盖成别的卷子"常见得多，
每次都弹窗拦一道会拖慢讲评节奏。状态栏黄字足够醒目。

### 2.4 内容指纹：`SHA256(长度 ‖ 前 1 MiB ‖ 后 1 MiB)`

- **不用 文件长度 + 修改时间**：老师拷来拷去（U 盘、一体机、微信传一遍），修改时间几乎必然改变，
  而内容其实一模一样 —— 那样每次打开都会误判成"对不上"。
- **不整份哈希**：一份上百 MB 的扫描版试卷全量哈希会让打开文档卡顿。
- **取首尾各 1 MiB**：全文件哈希对"重新下载的试卷"没有必要，而对 4.5 MiB 的样本试卷就是全量哈希。
  实测 4.47 MiB 的样本，只在哈希窗口外改动一个字节 → 指纹不变（**这条已知取舍已写进验收断言**，
  免得日后有人误以为它是密码学哈希）。

### 2.5 保存时机：自动兜底 + 关键节点强制 + 手动

| 触发 | 时机 |
|---|---|
| 自动 | 停止书写 **2 秒**后（每次修改重置计时） |
| 强制 | 切文档前、关文档前、关窗口前 |
| 手动 | `Ctrl+S` / 工具栏「保存批注」 |

课堂上一份卷子讲 40 分钟，最怕的是"写了满屏批注，程序崩了全没了"。所以自动保存不是可选项。

反过来，写字时每一笔都会改动 `StrokeCollection`，若逐次落盘，一次板书会触发上百次写入 ——
所以用"停笔后延迟"的防抖，两个毛病一起解决。

### 2.6 写盘用「临时文件 + 原子替换」

```
写 <path>.tmp  →  File.Replace(tmp, path) 或 File.Move(tmp, path)
```

直接覆写的话，一旦写到一半断电/崩溃，批注文件就是半截垃圾 —— **那比没有更糟**：
下次打开会解析失败，连"重来一次"的机会都没有。

## 3. 五个坑（都写在代码注释里）

| 坑 | 后果 | 对策 |
|---|---|---|
| **加载笔迹会被记进撤销历史** | Ctrl+Z 一次把整份"恢复的批注"全撤销掉，一按全没 | `InkHistory.Silently(Action)`：抑制记录地执行一段操作；`ReplaceStrokes` 走它，随后再 `Reset()` |
| **换文档时旧的待保存任务还在计时** | timer 醒来把**旧卷子的批注写进新卷子的文件** | 换文档时先 `Flush` 再 `Cancel` |
| **`Document.FilePath` 在事件里已经是新值** | 保存时把旧批注写进新文件，静默无提示 | 视图层自己维护 `_annotatedPath`（笔迹**归属**的路径） |
| **空笔迹时留着旧文件** | 全擦光后重开，批注"复活" | 笔迹为 0 条 ⇒ **删除**侧车文件 |
| **只读目录（U 盘写保护）保存失败** | 抛异常 → 崩溃；每 2 秒弹窗 → 灾难 | 捕获 → 日志 + 状态栏黄字，**不弹窗**；并清掉脏标记避免无休止重试 |

### 附：一条新发现 —— ISF 不是位精确格式

实测数据：

```
存入：首点 (100, 120)          笔宽 4.0
读回：首点 (100.00629921259842, 120)   笔宽 3.9999874017370027
```

ISF 内部按量化的物理单位存储，往返必然带来约 **0.006 world 单位**的误差
（换算到 1.6 倍缩放的屏幕上约 0.01 px，肉眼与数位板都感知不到）。

两个实际含义：

1. **验收断言不能用"逐位相等"** —— 那是比格式本身更严的要求。容差放到 0.05 world。
2. **反复存盘/读取不会累积漂移** —— 量化是收敛的，第二次读回的值与第一次相同。

## 5. 验收数据（harness 全绿，退出码 0）

### 5.1 往返保真

```
保存：944 字节 → 批注已保存（2 条）
ISF 往返量化误差：首点 X 偏移 0.006299 world（≈0.0101 px @1.6x，不可见）
[PASS] 两个笔画的采样点在 0.05 world 内一致（世界坐标零换算）
[PASS] 墨色与笔宽原样保留（红 4.0 / 蓝 0.8）
[PASS] 原子写没有留下 .tmp 残骸
```

### 5.2 损坏容忍

```
5 字节垃圾文件 → Rejected：文件过短，不是批注文件
版本号 99 的文件 → Rejected：批注文件版本 99 高于本程序支持的 1，请升级程序后再打开
```

### 5.3 指纹

```
样本 4.47 MiB，指纹 = 5131881f5590a2bd47f20b34c996a5c3
[PASS] 同一文件多次计算结果一致（与修改时间、路径无关）
[PASS] 改动首部字节后指纹改变
[PASS] 已知取舍：只改中间字节时指纹不变
```

### 5.4 四层判定

```
页数对不上        → Rejected：批注属于另一份文档（批注 7 页，当前 6 页）
版式对得上但指纹不同 → LoadedWithMismatch：⚠ 这份 PDF 与批注记录的不是同一份文件，批注位置可能不准
```

### 5.5 平移补偿

```
批注记录的页面在 (x+100, y+50)，当前版式整体左移上移
笔迹首点 (100,120) → 补偿后 (0.0, 70.0)
```

### 5.6 撤销历史不被污染

```
装载前 CanUndo=True → 装载后 CanUndo=False、笔迹 2 条
```

### 5.7 自动保存

```
标记脏 → IsDirty=True；Flush → 累计写入 1 次、清脏 = True
停笔后计时器自动落盘：触发 1 次
[PASS] 不脏时 Flush 是空操作（不会把没变的内容反复写盘）
[PASS] 挂起期间不置脏（装载批注不会被当成「用户改了东西」）
```

### 5.8 端到端（最关键）

```
保存前蓝线像素 10708 个（外接框 766×49 px）
重启后蓝线像素 10707 个（外接框 766×49 px）
差异 1 个像素（0.01%，全部来自 ISF 量化导致的抗锯齿边缘翻边）
```

证据图：`artifacts/m6-smoke/m6-1-before-save.png`、`m6-2-after-restart.png`。
完整输出：`artifacts/m6-smoke/verify-m6.txt`。

## 6. 一体机实测清单（M6 部分）

> 前两组（M4 笔/橡皮/笔尾、M5 撤销）见 `docs/05` 与 `07`，这里只列 M6 新增。

| # | 操作 | 期望 |
|---|---|---|
| 12 | 打开试卷，写几笔，等 2 秒 | 状态栏变成「批注已保存 hh:mm:ss」，试卷旁出现 `.tbink` |
| 13 | 关掉程序，重新打开同一份试卷 | 之前的批注**原样回来**，且在原来的位置上 |
| 14 | 写几笔后立刻按 `Alt+F4` 关窗口（不等自动保存） | 重新打开 → 刚才那几笔也在（关窗口前的强制落盘生效） |
| 15 | 擦掉全部笔迹，等 2 秒 | `.tbink` 文件消失；重新打开 → 干净的一张卷子 |
| 16 | 打开另一份试卷 | 状态栏不该出现上一份卷子的批注；两份卷子的批注互不干扰 |
| 17 | 拷到一体机的场景 | 把 PDF 和同名 `.tbink` **一起**拷过去，打开即见批注 |

**可能的失败形态与含义**：

- 状态栏一直显示「● 批注未保存」→ 落盘失败。看日志（`%LOCALAPPDATA%\MathPhys.Ink\logs\`），
  多半是目录只读（U 盘写保护）或权限不足。**这不是数据损坏**，批注还在内存里，换可写目录即可。
- 状态栏出现黄字「⚠ 这份 PDF 与批注记录的不是同一份文件」→ 这个 PDF 曾被同名覆盖过。
  批注照常可用，但位置请核对一眼。

## 7. 与后续里程碑的关系

- **笔迹从 M6 起落盘**，但**只落笔迹**：工具切换、墨色选择、视口位置都不持久化（有意为之）。
- **M6 不做**：把批注烧进 PDF 导出（这会生成一份带批注的新 PDF，属于导出功能，另立里程碑）；
  跨页擦除；批注的版本管理/多套批注。
- 撤销历史仍然只活在内存里，**关掉程序即清空** —— 这是正确的：历史是"这次会话的编辑过程"，
  不是文档内容。
