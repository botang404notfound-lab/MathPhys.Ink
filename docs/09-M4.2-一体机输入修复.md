# M4.2 一体机输入修复（红外触摸框上无法书写 / 全屏覆盖）

> 这一版不是新功能里程碑，而是 M4 在**真实一体机上被推翻后的修正**。
> 触发于 2026-09-21 首次教室实测，附带一份现场日志。

---

## 1. 现场现象

用户在希沃一体机上试出三条：

1. **只能"窗口全屏"**，期望达成全屏幕覆盖（无边框、盖住任务栏）。
2. **点了「笔」或「橡皮」之后，其他按钮全部点不动，必须退出程序重进。**
3. **用笔写上去的字，笔一离开屏幕就自动消失。** 同一程序在电脑上用鼠标操作一切正常。

第 3 条发生在这台机器上时，第 2 条的后果是：其余功能没法测。

---

## 2. 决定性证据

用户的日志（`%LOCALAPPDATA%\MathPhys.Ink\logs\2026-09-21.log`）全文只有 4 条记录，
对应 4 次启动，**每一条都长这样**：

```
stylus: type=Touch name="HID Interface" inverted=False → 抑制
```

两条推论，直接改写了整个输入策略：

| 观察 | 推论 |
|---|---|
| **从来没有出现过 `type=Stylus`** | 这台一体机上，**笔在系统看来就是一根手指** |
| 设备名是通用的 `HID Interface`，`inverted` 恒为 `False` | 红外触摸框 + 被动笔：无压力、无悬停、无反转信号 |

**这是硬件决定的，不是驱动没装好。** 红外触摸屏靠"哪一处的红外被遮挡"定位，
硬件层面拿不到"这是笔还是手指"的信息。所以：

- M4 设计的「笔尾反转随手擦」在这台机器上**不可能工作**（`Inverted` 永远为 false）；
- M4 设计的「按 `TabletDeviceType` 区分笔与手指」在这台机器上**不成立**（两者同为 `Touch`）。

---

## 3. 根因：一个缺陷，解释了三个现象中的两个

M3/M4 的写法是：把"不该落墨"的输入在 `PreviewStylus` 阶段 `e.Handled = true` 掐掉。
在一体机上，`Touch` 被判定为"手指 / 手掌"⇒ **每一次笔输入都被掐掉**。

但"掐掉"这个动作本身是坏的，而且坏得很难看：

### 3.1 写的字抬笔就消失

WPF 的实时墨迹由 `DynamicRenderer` 绘制，它是个 `StylusPlugIn`，
**跑在笔输入线程上，根本不看 `Handled`**。于是：

```
落笔 → DynamicRenderer 照画（你看到了字）
     → UI 线程的正式采集被 Handled 挡住（一笔都没采集）
抬笔 → 没有正式笔画提交 ⇒ DynamicRenderer 清掉它那层临时墨迹
     ⇒ "写上去的字，笔一离开就消失"
```

**看起来写了，其实一笔都没存下来。** 这也解释了为什么"看着像能写"——
因为实时层确实在工作，坏的只是提交这一段。

### 3.2 必须退出重进

同一根因的另一面。采集被半途打断会把**输入捕获**留在悬空状态。
而红外屏上**所有触点共用同一个输入设备**，捕获一旦没释放，
后续每一次触摸都被直送墨迹层 —— **所有按钮都变成点不动**，只有退出进程能解。

### 3.3 鼠标为什么正常

鼠标报 `TabletDeviceType.Stylus`，走的是"落墨"分支，从来没进过这条坏路径。
这恰好反证了根因（当时日志里那 4 条 `Touch` 全部被判成"抑制"）。

> **补充**：这个缺陷在有真笔数字化仪的平板上同样存在（手指被 `Handled` 后一样会卡住输入），
> 只是本机没有触摸屏，M4 那套策略从未被真实触摸验证过。

## 4. 修复

### 4.1 设备类型退出决策，改回「工具即模式」

```
手工具    → 不落墨
橡皮工具  → 擦除
笔工具    → 落墨（笔尾反转时擦除，仅当驱动报得出反转标志）
```

`InkInputPolicy.Decide` 的签名从 `(tool, deviceType, inverted)` 收敛为 `(tool, inverted)`。
harness 用**反射**钉住了这一点（见 §5），因为"把 `deviceType` 加回去"看起来是个
很合理的改动，而它一旦发生，红外屏上笔又会被当成手指。

**彻底删掉 `e.Handled = true` 这条抑制路径** —— 它挡不住实时层，还会泄漏捕获。

### 4.2 「不要落墨」改用确定有效的手段

手工具下靠 `IsHitTestVisible = false`：输入根本不路由到墨迹层，连实时层都不会启动。
这比 `Handled` 干净，且 M3 起就被验证过。

### 4.3 触摸归属按工具二选一

`IsManipulationEnabled` 跟随工具：

| 工具 | Manipulation | 触摸去向 |
|---|---|---|
| 笔 / 橡皮 | **关** | 提升为笔事件 → 落墨 / 擦除 |
| 手 | **开** | 单指平移、双指捏合缩放 |

理由：WPF 里 Manipulation 与"触摸提升为笔事件"是**两条互相抢输入的路径**，
而且 Manipulation **无法按手指数过滤**（单指落下也会启动它）。
两个都开着会同时落墨又平移，并把墨迹采集打断。

**代价（已知并接受）**：笔/橡皮工具下不能双指捏合缩放，需切到「手」工具，
或用滚轮 / Ctrl+滚轮 / 工具栏按钮。

### 4.4 捕获保险

三处兜底复位，专治"程序还在、操作全失灵"：

- `OnLostMouseCapture` —— 复位 `_panning` 与光标
- `OnLostTouchCapture` —— 从触点表移除该触点
- `OnManipulationCompleted` —— 清空触点表、复位平移

另加一道：触点表超过 8 个（明显异常）时整体重建。

### 4.5 全屏覆盖

不用 `WindowState.Maximized`：WPF 计算最大化尺寸时仍按"带边框"的窗口矩形算，
右边和底下会各被裁掉几个像素。改为**手动铺满主屏尺寸**（`PrimaryScreenWidth/Height`，
不是 `WorkArea` —— 后者会扣掉任务栏）。

退出方式：**F11** 切换、**Esc** 退出全屏（退出后标题栏与关闭按钮就回来了）。
**另见 §9**：这里当初只留了键盘退路，在没插键盘的一体机上等于没有退路，
已在 M7.2.1 补上界面按钮并让程序记住上次的选择。

### 4.6 日志重做

原来的日志只有"设备签名"，不够定位。现在分两层：

- **启动时 dump 全部输入设备**（id / 类型 / 名称）+ 一句判定；
- **关窗口时输出事件汇总**，并做交叉校验：
  `stylus.down vs stylus.up`、`touch.down vs touch.up` 是否配对
  —— **不配对就是"输入序列被截断"的直接证据**。

另有一次性事实立即记录：设备签名、**触摸接触面积**（手掌拒绝的唯一可能依据）、
笔画提交计数。

## 8. 已知限制与后续

1. **笔尾擦除在这台机器上不会工作** —— 红外被动笔没有反转信号，
   `inverted` 恒为 `false`。程序里的 `EditingModeInverted` 配置保留着，
   换到有真笔数字化仪的机器上就直接生效。
2. **笔与手指无法区分** —— 见 §2，硬件层面就没有这个信息。
   若实测第 10 条发现"扶屏的手会画墨"，唯一的软件出路是**接触面积**：
   日志里的 `接触面积=` 就是为此准备的探针。若显示「无面积数据」，
   说明驱动不提供尺寸，那这条路也走不通，只能靠「手」工具手动规避。
3. **笔/橡皮工具下不能双指缩放** —— 见 §4.3，是有意取舍。

## 9. 补丁：窗口模式可切换（M7.2.1，2026-09-21）

### 9.1 问题（用户实测反馈）

> "每次打开软件会自动全屏，界面内没有切换窗口模式的功能。"

这不是"少了颗按钮"这么简单 —— **§4.5 只给了 F11 / Esc 两条退路，两条都在键盘上**。
一体机的键盘常常不在手边（或根本没接），于是老师进去就出不来：
想关窗口、想切别的程序、想看桌面，全都没有出路。
**一个只能用键盘解的默认值，在触屏设备上就是 bug。**

### 9.2 修复（3 处）

| 位置 | 改动 |
| --- | --- |
| `MainWindow.xaml` | 工具栏容器由 `WrapPanel` 改为 `DockPanel`，最右上角 `Dock=Right` 常驻一颗 `WindowModeButton` |
| `MainWindow.xaml.cs` | 抽出 `UpdateWindowModeButton()`（文案写"点了会变成什么"）+ `OnToggleWindowModeClick` → 复用既有 `ToggleFullScreen()` |
| 新增 `Infrastructure/UiStateStore.cs` | 把"上次是不是全屏"记到 `%LOCALAPPDATA%\MathPhys.Ink\ui-state.txt`，下次启动跟随 |

**为什么必须 `Dock=Right` 而不是排在工具按钮后面**：工具按钮在 `WrapPanel` 里，
窗口一窄就换行、被挤到第二行甚至可视区之外 —— 对一颗"唯一的退路"按钮来说，
"可能被挤走"等于不存在。钉死在右上角，任何窗口宽度下都点得到。

**为什么记状态**：默认全屏是给一体机讲评用的（M4.2 的原始需求），不能一刀切改掉；
但"每次启动都要先点一下"也是负担。**首次默认全屏 + 之后跟随用户的选择**，两边都照顾到。
状态文件刻意用一行文本而不是 JSON：用记事本就能看懂、能改回来，
它坏了也只该回落到出厂默认，不该让程序起不来（读写都吞异常）。
